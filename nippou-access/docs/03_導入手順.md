# 導入手順

## 用意するもの

- Microsoft Access（製品版）。2016 以降を想定
- 共有フォルダ 1 つ（現行の `\\fsx.sales.mint.go.jp\share\share_電話オペレータ\` 配下でよい）

---

## 手順 1 ― 空の Access ファイルを作る

1. Access を起動 → 「空のデータベース」
2. ファイル名を `日報集計.accdb` にして、作業用のローカルフォルダに作成

---

## 手順 2 ― VBA モジュールを入れる

`Alt` + `F11` で VBE を開き、次のどちらかで 7 本のモジュールを入れます。

### A. 貼り付ける（推奨・確実）

1. 「挿入」→「標準モジュール」
2. `dist/modSetup.bas` の中身を全部コピーして貼り付け
3. 先頭の `Attribute VB_Name = "modSetup"` の行は貼り付け時に消えるので、
   VBE 左のプロパティで **モジュール名を `modSetup` に変更**
4. 残り 6 本も同様に

| 順 | モジュール名 |
|---|---|
| 1 | `modSetup` |
| 2 | `modSetupMaster` |
| 3 | `modSetupQuery` |
| 4 | `modSetupUI` |
| 5 | `modSetupReport` |
| 6 | `modApp` |
| 7 | `modImportExcel` |

### B. インポートする

「ファイル」→「ファイルのインポート」で `dist/*.bas` を選ぶ。
`dist/` は Shift_JIS + CRLF に変換済みなので文字化けしません。
（`src/` は UTF-8 なのでインポートには使わないこと）

### 参照設定の確認

VBE の「ツール」→「参照設定」で次にチェックが入っていることを確認します。
通常は既定で入っています。

- Visual Basic For Applications
- Microsoft Access xx.x Object Library
- **Microsoft Office xx.x Access database engine Object Library**（DAO）

---

## 手順 3 ― `Setup_All` を実行する

1. `modSetup` を開き、`Setup_All` の中にカーソルを置く
2. `F5`
3. 「セットアップが完了しました」が出れば成功（1 分ほどかかります）

出来上がるもの:

- テーブル 11 本（マスタ 6 / 実績 5）
- マスタデータ（製品 45 / 区分 68 / 担当者 18 / 業務項目 13）
- クエリ 15 本
- 画面 13 本
- 帳票 3 本

`Setup_All` は**何度実行しても同じ結果**になります。マスタと画面は毎回作り直し、
`T_` で始まる実績データは保持されます（`modSetup` の `DROP_DATA_TABLES` が
`False` の間）。

---

## 手順 4 ― 過去データを取り込む

メニューの「Excel から取込」→ `集計表（…）.xlsm` を選びます。
週ごとの集計表ファイルがある分だけ繰り返してください。

取込は `日付・担当者・区分・製品` が同じ行を上書きするので、
同じファイルを 2 回取り込んでも二重にはなりません。

### 事前検証の結果

`tools/verify_migration.py` で `集計表（ＶＢＡ版）.xlsm` を実際に流したところ:

```
成功 306 行 / 引き当て失敗 0 行 / 対象外 65 行（見出し・SUMIF 用の空行）
日別・集計列別の合計は、Excel の生データと全日付で一致
```

つまり**マスタの引き当て自体は全行通ります**。ただし取込後に
次の 2 点を手で直す必要があります。

| 直すもの | 内容 |
|---|---|
| `100 顧客Ｇ` に付いた 17 行 37 件 | 現行の設定ミスで **002堀・004谷口・006国森・009西岡・015鈴木** の 5 名分が混ざっています。誰の分かは元の Excel からは判別できません |
| `015 鈴木` に付いた 29 行 53 件 | 現行データの担当者欄は「鈴木」という姓だけで、**015鈴木さんと 018鈴木智さんの区別が付きません**。実際には 015 の `B1` が「顧客G」だったので、この 29 行は 018鈴木智さんの分である可能性が高いです |

取込前に確認したい場合は、Windows を使わずに次で検算できます。

```bash
python3 tools/verify_migration.py --src <xlsm を置いたフォルダ>
```

引き当てられなかった行は `T_取込ログ` に理由つきで残ります。多くは:

- **担当者名が「顧客G」になっている行** ―― 現行の設定ミスで
  堀・谷口・国森・西岡・鈴木の 5 名分が混ざっています。
  誰の分かは元の Excel からは判別できないので、手で振り分けるか、
  「顧客G」のまま残すかを決めてください
- **区分名が旧名のまま** ―― `M_区分.旧転記名` で引き当てているので通常は通ります。
  通らない場合はマスタ保守で `旧転記名` を補ってから再取込してください

## 手順 5 ― フロントエンドとバックエンドに分ける

複数人で同時に使うので、**必ず分割**してください。分割しないと
共有フォルダ上の 1 ファイルを全員が開くことになり、破損の危険があります。

1. Access の「データベース ツール」→「Access データベース」（データベース分割ツール）
2. バックエンド（`日報集計_be.accdb`）を**共有フォルダ**に置く
3. フロントエンド（`日報集計.accdb`）を**各 PC のローカル**にコピーして配る

```
\\fsx…\share_電話オペレータ\日報\
    日報集計_be.accdb          ← データ。ここだけ共有
    配布用\日報集計.accdb      ← 各自がローカルにコピーして使う
```

### なぜフロントエンドを各 PC に置くのか

- 共有フォルダ上のフロントエンドを全員が直接開くと、一時オブジェクトの
  競合でファイルが壊れやすくなります
- ローカルに置けば、画面の描画がネットワーク越しにならず速くなります

### バックエンドを更新したとき

`Setup_All` を実行し直して分割し直すか、新しいフロントエンドを配り直します。
**実績データはバックエンド側にあるので消えません。**

---

## 手順 6 ― 起動時の設定

`Setup_All` が次を自動で設定します。

- アプリケーションタイトル: 「電話応対日報 集計システム」
- 起動時に開くフォーム: `F_メニュー`

ナビゲーションウィンドウは表示したままにしてあります。運用が落ち着いたら
「ファイル」→「オプション」→「現在のデータベース」で非表示にしてください。

---

## つまずきやすいところ

| 症状 | 対処 |
|---|---|
| `Setup_All` で「ユーザー定義型は定義されていません」 | 参照設定で DAO（Access database engine Object Library）にチェック |
| コンボボックスが空 | `Q_選択_担当者` は**今日時点で在籍**の人だけ。`M_担当者.在籍終了日` を確認 |
| 帳票の氏名欄が空 | その日の `T_出勤` が空。日報画面の「在籍者を一括登録」を押す |
| 「レコードは削除されました」 | マスタを作り直した直後に古い画面が開いていた。画面を閉じて開き直す |
| 取込で「外部データベースを開けません」 | Excel ファイルが他の人に開かれている。閉じてから再実行 |
