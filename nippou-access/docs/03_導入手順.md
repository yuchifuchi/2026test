# 導入手順

## いちばん短い手順

1. **`dist/日報集計_be.accdb` を共有フォルダに置く**
2. **`web/` を IIS に置き、3 か所を書き換える**（[05 Web 版](05_Web版.md)）

これで終わりです。**Access は 1 台も要りません。**

`日報集計_be.accdb` は、表・マスタ・つながりまで入った状態でお渡ししています。
中に VBA は入っていないので、開いてもマクロの警告は出ません。

```
\\fsx…\share_電話オペレータ\日報\
    日報集計_be.accdb          ← これ 1 つにすべてのデータが入る
    日報集計_be.laccdb         ← 誰かが使っている間だけできる目印 (消さない)
```

置き場所は、**毎日バックアップされるフォルダ**を選んでください。
Web サーバーからは「読み取り」だけでなく**書き込み**もできる必要があります
（ACE がロックファイル `.laccdb` を同じフォルダに作るため）。

---

## 中に何が入っているか

| 種類 | 数 | 中身 |
|---|---|---|
| 表 | 11 | マスタ 6（集計列・ブロック・製品・区分・担当者・業務項目）＋ 実績 5 |
| マスタの初期データ | 158 件 | 製品 45 / 区分 68 / 担当者 18 / 業務項目 13 / 集計列 6 / ブロック 8 |
| 表どうしのつながり | 8 | 参照整合性つき。使われているマスタは消せない |
| 実績 | 0 件 | 使い始めた日から貯まります |

**保存クエリ（`Q_…`）は入っていません。** Web 版は SQL を
`web/include/sql.asp` に持っており、Access 側のクエリに依存しません。
理由は 2 つあります。

- Access を 1 台も使わずに `.accdb` を作れるようにするため
- ACE（Web からの接続）では `Nz()` のような Access 専用関数が使えず、
  「Access の中では動くのに Web からだけ失敗する」形を避けるため

### 作り直したいとき

`dist/データベースを作る.vbs`（Access のあるパソコンでダブルクリック）か、
開発環境なら次で作り直せます。

```bash
python3 tools/gen_accdb.py dist/日報集計_be.accdb   # Windows も Access も不要
python3 tools/test_sql.py                          # ASP が流す SQL を実際に通す
```

どちらも出どころは `src/*.bas` 1 つなので、中身は同じになります。

## 任意 A ― 過去データを取り込む

いままでの `集計表（…）.xlsm` を新システムに入れたいときだけの作業です。
**新しく使い始めるだけなら要りません。**

Access が 1 台必要です。`日報集計_be.accdb` を Access で開き、
`Alt`+`F11` →「ファイル」→「ファイルのインポート」で `dist/modSetup.bas` と
`dist/modImportExcel.bas` を読み込み、`Import_Excel_Dialog` を `F5` で実行します。

取り込む `集計表（…）.xlsm` を選びます。
週ごとの集計表ファイルがある分だけ繰り返してください。

取込は `日付・担当者・区分・製品` が同じ行を上書きするので、
同じファイルを 2 回取り込んでも二重にはなりません。

### 事前検証の結果

`tools/verify_migration.py` で `集計表（ＶＢＡ版）.xlsm` を実際に流したところ:

```
成功 306 行 / 引き当て失敗 0 行 / 対象外 65 行（見出し・SUMIF 用の空行）
日別・集計列別の合計は、Excel の生データと全日付で一致
```

つまり**マスタの引き当て自体は全行通ります**。ただし取込後に
次の 2 点を手で直す必要があります。

| 直すもの | 内容 |
|---|---|
| `100 顧客Ｇ` に付いた 17 行 37 件 | 現行の設定ミスで **002堀・004谷口・006国森・009西岡・015鈴木** の 5 名分が混ざっています。誰の分かは元の Excel からは判別できません |
| `015 鈴木` に付いた 29 行 53 件 | 現行データの担当者欄は「鈴木」という姓だけで、**015鈴木さんと 018鈴木智さんの区別が付きません**。実際には 015 の `B1` が「顧客G」だったので、この 29 行は 018鈴木智さんの分である可能性が高いです |

取込前に確認したい場合は、Windows を使わずに次で検算できます。

```bash
python3 tools/verify_migration.py --src <xlsm を置いたフォルダ>
```

引き当てられなかった行は `T_取込ログ` に理由つきで残ります。多くは:

- **担当者名が「顧客G」になっている行** ―― 現行の設定ミスで
  堀・谷口・国森・西岡・鈴木の 5 名分が混ざっています。
  誰の分かは元の Excel からは判別できないので、手で振り分けるか、
  「顧客G」のまま残すかを決めてください
- **区分名が旧名のまま** ―― `M_区分.旧転記名` で引き当てているので通常は通ります。
  通らない場合はマスタ保守で `旧転記名` を補ってから再取込してください

## 任意 B ― Access のデスクトップ画面も使う

Web 版だけで運用するなら**不要**です。停電やサーバー停止のときの予備として、
Access 側にも入力画面と帳票を持たせたい場合の手順です。

1. 空の `.accdb` を作り、`Alt`+`F11` →「ファイル」→「ファイルのインポート」で
   `dist/` の 7 ファイルを読み込む（順番は問いません。名前は自動で付きます）
2. `modSetup` の `Setup_All` にカーソルを置いて `F5`
   （テーブル 11・マスタ・クエリ 15・画面 13・帳票 3 ができます）
3. 「データベース ツール」→「Access データベース」で前後に分割し、
   バックエンドを**すでに共有フォルダにある `日報集計_be.accdb` に差し替える**
4. フロントエンド（`日報集計.accdb`）を各 PC のローカルにコピーして配る

```
\\fsx…\share_電話オペレータ\日報\
    日報集計_be.accdb          ← データ。ここだけ共有
    配布用\日報集計.accdb      ← 各自がローカルにコピーして使う
```

### なぜフロントエンドを各 PC に置くのか

- 共有フォルダ上のフロントエンドを全員が直接開くと、一時オブジェクトの
  競合でファイルが壊れやすくなります
- ローカルに置けば、画面の描画がネットワーク越しにならず速くなります

### バックエンドを更新したとき

`Setup_All` を実行し直して分割し直すか、新しいフロントエンドを配り直します。
**実績データはバックエンド側にあるので消えません。**

---

### Access 側の起動時の設定

`Setup_All` が次を自動で設定します。

- アプリケーションタイトル: 「電話応対日報 集計システム」
- 起動時に開くフォーム: `F_メニュー`

ナビゲーションウィンドウは表示したままにしてあります。運用が落ち着いたら
「ファイル」→「オプション」→「現在のデータベース」で非表示にしてください。

## つまずきやすいところ

| 症状 | 対処 |
|---|---|
| Web から「Provider が見つかりません」 | サーバーに Microsoft Access Database Engine 2016 Redistributable が入っていない。またはアプリケーションプールのビット数が合っていない |
| Web から「ファイルを開けません」「排他的に開けません」 | `.accdb` を置いた**フォルダ**にアプリケーションプール ID の変更権限が無い。読み取りだけでは動きません |
| `Setup_All` で「ユーザー定義型は定義されていません」 | 参照設定で DAO（Access database engine Object Library）にチェック |
| コンボボックスが空 | `Q_選択_担当者` は**今日時点で在籍**の人だけ。`M_担当者.在籍終了日` を確認 |
| 帳票の氏名欄が空 | その日の `T_出勤` が空。日報画面の「在籍者を一括登録」を押す |
| 「レコードは削除されました」 | マスタを作り直した直後に古い画面が開いていた。画面を閉じて開き直す |
| 取込で「外部データベースを開けません」 | Excel ファイルが他の人に開かれている。閉じてから再実行 |
