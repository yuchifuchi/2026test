## 0. あなたの役割

あなたは、官公庁の小さな課（10 名程度）で使う業務システムを、
**設置も運用も情報システム部門なしで回せる形**で作り切るエンジニアです。

利用者は IT 担当者ではありません。Excel は使えますが、
コマンドプロンプトは開いたことがありません。
**「手順書どおりにファイルをコピーすれば動く」ところまでが成果物**です。
コードが動くだけでは未完成とみなします。

出力する日本語（画面の文言・手順書・コード内のコメント）は、
すべてこの利用者が読んで分かる言葉にしてください。
「デプロイ」「バインド」「インスタンス」などのカタカナ技術用語は、
手順書と画面では使わないでください。

## 1. 作るもの

造幣局 販売・顧客サービス課の **「電話応対報告書 日報集計システム」**。

電話オペレーター（パート職員 5〜7 名）が 1 日に受けた電話を区分ごとに記録し、
正規職員がそれを 1 枚の日報（A4 縦）にまとめて印刷し、
週単位の集計表も出せるようにします。

### 現行（置き換え対象）

Excel マクロ。次の構成です。

- `001〜00N 記入用フォーム.xlsm` … オペレーター 1 人に 1 ファイル。各自が自分のファイルに入力
- `日報集計印刷用フォーム.xlsm` … 全員ぶんを「吸い出して」集計し、印刷する親ファイル
- 親ファイルのマクロが各ファイルを開いて値をコピーしてくる

### 現行で起きている不具合（必ず再発させないこと）

1. **特定の人のデータだけ吸い出せない**
   原因：各記入用フォームの `Sheet1!B1`（担当者名）が、ファイル番号とズレている。
   6 ファイルで別人の名前が入っていた。親マクロは名前で突き合わせるため、
   名前がズレたファイルは「該当者なし」で黙って飛ばされる。
2. **数値が合わない**
   原因：集計表の `SUMIF` の範囲が行ごとに 1 行ずつズレている（相対参照のドラッグ）。
   さらに集計表を前日の値のままクリアせず上書きしているため、
   入力が減った日は前日の数字が残る。
3. **日付が勝手に変わる**
   原因：`=TODAY()` を保存しているため、翌日開くと別の日になる。
4. **フォントサイズが勝手に変わる**
   原因：セルの「縮小して全体を表示する」が効いている。
5. **エラーが出ない**
   原因：マクロ全体が `On Error Resume Next` で囲まれており、
   失敗しても「完了しました」と出る。

**この 5 つが構造的に起きない作りにすること。**
とくに「数値の出どころを 1 本にする」こと（下記 3 章）。

## 2. 技術構成（これは決定事項。変更提案は不要）

```
   パート職員の PC ─┐
                    ├─ ブラウザ ─→ IIS (Windows Server) ─→ 日報集計_be.accdb
   正規職員の PC   ─┘              Classic ASP (VBScript)      (データ置き場のみ)
```

- **画面**：Classic ASP（VBScript）＋ 素の HTML/CSS。
- **データ**：Microsoft Access のファイル（`.accdb`）1 個。
  **ただし Access は「データの入れ物」としてしか使いません。**
  フォームもレポートも保存クエリも作りません（理由は 4 章）。
- **接続**：ADO ＋ `Microsoft.ACE.OLEDB.12.0`。
- **PDF**：サーバーにある Microsoft Edge をヘッドレスで呼んで HTML → PDF。

### なぜこの構成なのか（勝手に変えないための背景）

- 利用者の PC に新しいソフトを入れられない。ブラウザだけで使えること。
- サーバーに .NET ランタイムや Node.js を入れる申請が通らない。
  **IIS と Classic ASP は Windows Server に最初から入っている**ので申請が要らない。
- SQL Server を立てる予算と管理者がいない。Access ファイルなら共有フォルダに置くだけ。
- 同時に入力するのは最大 7 人。Access の同時接続の制約内に収まる。

### やってはいけない代替案

- ASP.NET / Node.js / Python / PHP への変更（サーバーに入れられない）
- SQL Server / MySQL / SQLite への変更（運用できる人がいない）
- npm / NuGet / pip などの外部ライブラリの導入（ネットワークが閉じている）
- CDN 参照の JavaScript / CSS フレームワーク（外部に出られない）
- 利用者の PC に Access をインストールする前提の設計

**JavaScript は「無くても全機能が使える」範囲に留めてください。**
画面遷移と保存はすべて `<form method="post">` のサーバー側処理で完結させること。

## 3. データベース設計（この通りに作る）

### 設計の要

**数値の出どころを `T_受電` ただ 1 つにすること。**
日報の紙・集計表・画面の合計を、すべて同じテーブルから計算します。
現行 Excel は「入力シート → 転記シート → 集計表」と経路が 2 本あり、
そこで数字が食い違っていました。経路を 1 本にすれば構造的に食い違えません。

### マスタ

```sql
CREATE TABLE [M_集計列] (
  [集計列ID] LONG NOT NULL CONSTRAINT [PK_集計列] PRIMARY KEY,
  [集計列名] TEXT(50) NOT NULL,
  [表示順] LONG NOT NULL)
-- 日報の「申込／抽選／払込用紙／商品発送／その他」の 5 列

CREATE TABLE [M_ブロック] (
  [ブロックID] LONG NOT NULL CONSTRAINT [PK_ブロック] PRIMARY KEY,
  [ブロック名] TEXT(50) NOT NULL,
  [製品別] BIT NOT NULL,
  [表示順] LONG NOT NULL)
-- 入力画面の大きなまとまり。[製品別]=True なら製品を選ばせる

CREATE TABLE [M_製品] (
  [製品ID] LONG NOT NULL CONSTRAINT [PK_製品] PRIMARY KEY,
  [ブロックID] LONG NOT NULL,
  [製品名] TEXT(100) NOT NULL,
  [適用開始日] DATETIME,
  [適用終了日] DATETIME,
  [表示順] LONG NOT NULL,
  [有効] BIT NOT NULL)
-- 製品ID = 0 は「製品指定なし」として必ず 1 行入れておく

CREATE TABLE [M_区分] (
  [区分ID] LONG NOT NULL CONSTRAINT [PK_区分] PRIMARY KEY,
  [ブロックID] LONG NOT NULL,
  [区分名] TEXT(100) NOT NULL,
  [集計列ID] LONG NOT NULL,
  [内訳区分] TEXT(20),
  [表示順] LONG NOT NULL,
  [有効] BIT NOT NULL,
  [旧転記名] TEXT(100),
  CONSTRAINT [FK_区分_ブロック] FOREIGN KEY ([ブロックID]) REFERENCES [M_ブロック]([ブロックID]),
  CONSTRAINT [FK_区分_集計列] FOREIGN KEY ([集計列ID]) REFERENCES [M_集計列]([集計列ID]))
-- [集計列ID] が「この区分は日報のどの列に積むか」。
--   現行 Excel ではシートの 2 行目に埋め込まれていて、誰にも見えなかった情報。
-- [内訳区分] は "交換" / "返金"。日報の「内 交換 ○件／内 返金 ○件」に使う。
-- [旧転記名] は現行 Excel の表記。過去データ取り込みの突き合わせ用。

CREATE TABLE [M_担当者] (
  [担当者ID] LONG NOT NULL CONSTRAINT [PK_担当者] PRIMARY KEY,
  [担当者コード] TEXT(10) NOT NULL,
  [姓] TEXT(50) NOT NULL,
  [名] TEXT(50),
  [氏名] TEXT(100) NOT NULL,
  [カナ] TEXT(100),
  [ログオン名] TEXT(50),
  [職員区分] TEXT(10) NOT NULL,     -- "パート" / "職員"
  [在籍開始日] DATETIME,
  [在籍終了日] DATETIME,
  [表示順] LONG NOT NULL,
  [有効] BIT NOT NULL,
  [備考] MEMO)
CREATE INDEX [IX_担当者_コード]     ON [M_担当者] ([担当者コード])
CREATE INDEX [IX_担当者_ログオン名] ON [M_担当者] ([ログオン名])
-- 担当者は「削除」しない。在籍終了日を入れると入力画面の候補から消えるが、
-- 過去の日報・集計表はその担当者のまま残る。
-- 担当者コードは席番号で、人が替わると再利用される。だから UNIQUE は張らない。

CREATE TABLE [M_業務項目] (
  [業務項目ID] LONG NOT NULL CONSTRAINT [PK_業務項目] PRIMARY KEY,
  [番号] TEXT(4) NOT NULL,              -- "①" 〜 "⑬"
  [項目名] TEXT(100) NOT NULL,
  [帳票表示名] TEXT(100) NOT NULL,
  [表示順] LONG NOT NULL,
  [有効] BIT NOT NULL)
-- 日報の下段「電話対応以外の業務（データ入力作業等）」の ①〜⑬
```

### 実績

```sql
CREATE TABLE [T_日報] (
  [対象日] DATETIME NOT NULL CONSTRAINT [PK_日報] PRIMARY KEY,
  [回線数] LONG,
  [特記事項] MEMO,
  [職員代替案件] MEMO,
  [要望] MEMO,
  [状態] TEXT(10) NOT NULL,            -- "作成中" / "確定"
  [確定日時] DATETIME,
  [更新日時] DATETIME)

CREATE TABLE [T_出勤] (
  [出勤ID] COUNTER NOT NULL CONSTRAINT [PK_出勤] PRIMARY KEY,
  [対象日] DATETIME NOT NULL,
  [担当者ID] LONG NOT NULL,
  [勤務時間] TEXT(50),
  [備考] TEXT(255),
  CONSTRAINT [UQ_出勤] UNIQUE ([対象日],[担当者ID]))

CREATE TABLE [T_受電] (
  [受電ID] COUNTER NOT NULL CONSTRAINT [PK_受電] PRIMARY KEY,
  [対象日] DATETIME NOT NULL,
  [担当者ID] LONG NOT NULL,
  [区分ID] LONG NOT NULL,
  [製品ID] LONG NOT NULL,
  [件数] LONG NOT NULL,
  [備考2] TEXT(255),
  [備考3] TEXT(255),
  [登録日時] DATETIME,
  [更新日時] DATETIME,
  [登録者] TEXT(100),
  CONSTRAINT [UQ_受電] UNIQUE ([対象日],[担当者ID],[区分ID],[製品ID]))
CREATE INDEX [IX_受電_日付] ON [T_受電] ([対象日])
-- 1 行 = 1 (日付, 担当者, 区分, 製品) の件数。
-- 製品を伴わない区分は 製品ID = 0 を入れる。NULL を使わないことで
-- UNIQUE 制約が確実に効き、二重計上が構造的に起きない。

CREATE TABLE [T_業務実績] (
  [実績ID] COUNTER NOT NULL CONSTRAINT [PK_業務実績] PRIMARY KEY,
  [対象日] DATETIME NOT NULL,
  [担当者ID] LONG NOT NULL,
  [業務項目ID] LONG NOT NULL,
  [件数] LONG NOT NULL,
  CONSTRAINT [UQ_業務実績] UNIQUE ([対象日],[担当者ID],[業務項目ID]))
```

参照整合性（`T_受電` → `M_担当者` / `M_区分` / `M_製品`、`T_出勤` → `M_担当者`）も張ること。

## 4. Access の使い方の制約（ここが一番つまずく）

### 保存クエリを作らない

Access の保存クエリ（`Q_〜`）は **ACE OLEDB 経由で呼べますが、
中で Access 専用関数を使っていると実行時にしか落ちません。**
SQL は ASP 側の `include/sql.asp` に文字列として持たせ、
`SELECT ... FROM (ここにその SQL) AS D WHERE ...` の形で埋め込んで使ってください。

### `Nz()` は絶対に使わない

`Nz()` は **Access アプリケーションの関数**であり、
ACE OLEDB 経由（＝ ASP から）では **`関数 'Nz' は定義されていません` で落ちます。**
NULL を 0 にするときは必ず次を使ってください。

```sql
IIf(IsNull(Sum(W.[件数])), 0, Sum(W.[件数]))
```

ACE 経由で**使える**のは Jet Expression Service の関数だけです：
`IIf` `IsNull` `Date()` `Now()` `Format` `Nz 以外の基本関数`。

### 派生テーブルに `ORDER BY` で使う列を必ず含める

```sql
SELECT ... FROM (SELECT A.[名前] FROM ...) AS D ORDER BY D.[表示順]
```
は、内側の SELECT に `[表示順]` が無いと落ちます。
内側に必ず含めてください（現行開発でも 1 度ここで落ちました）。

### `.accdb` のファイル形式

**Access 2007–2016 形式（ファイル先頭 0x14 バイト目が `0x02`）で作ること。**
`0x05`（Access 2016 専用形式）で作ると、利用者の Access で開いたときに
**「このデータベースを開くには、Microsoft Access のより新しいバージョンが必要です」**
になります。作成後、必ずこのバイトを検査してください。

現場の Access は **Microsoft 365 Apps（クイック実行）／バージョン 2608 /
月次エンタープライズ チャネル** です。これでも `0x05` は開けません。
`0x02` にしておけば、Access 2010 以降のどれでも開けます。

## 5. 画面の構成と、役割の分け方

### 役割

| | パート職員 | 正規職員 |
|---|---|---|
| 受付入力（電話の件数） | ○ | ○ |
| その他業務の入力 | ○ | ○ |
| 日報の作成・確定 | × | ○ |
| 帳票の印刷（PDF） | × | ○ |
| 週の集計表 | × | ○ |
| 入力もれチェック | × | ○ |
| マスタ保守 | × | ○ |

### 分け方（これは決定事項）

**認証は一切行いません。IIS 側の設定もしません。**
**「置き場所（URL）を 2 つに分けるだけ」**で役割を分けます。

- パート職員には `…/nippou/part/` を、正規職員には `…/nippou/staff/` を知らせる
- **`part` フォルダには、職員用の画面ファイルそのものを入れない。**
  設定で止めるのではなく、ファイルが無いので開けない、という形にする
- Windows 認証は、設定の手間と「認証が出ない／二重に出る」の問い合わせが多く、
  現場の運用に合わない
- IP 制限も不要。課内の閉じたネットワークでしか使わない

**割り切り（これでよいと決まっています。提案し直さないでください）**
`staff` のアドレスを知っているパート職員は開けます。
不正入力の抑止ではなく、**「ふだん使う画面を間違えない」ための分離**です。
あとで絞りたくなったら IIS マネージャーの IP 制限で足せる、という位置づけに留めること。

### フォルダ構成（この通りに）

```
C:\inetpub\wwwroot\nippou\
├── part\            ← パート職員に知らせるアドレス
│   ├── default.asp        メニュー（受付入力・その他業務の 2 つだけ）
│   ├── entry.asp          受付入力
│   ├── tasks.asp          その他業務（①〜⑬ の件数）
│   ├── error.asp          エラー画面
│   ├── setup_check.asp    設置チェック
│   ├── probe1.asp 〜 probe7.asp   切り分け用（下記 8 章）
│   ├── web.config
│   ├── include\   (auth.asp / config.asp / db.asp / layout.asp / sheet.asp / sql.asp / pdf.asp)
│   └── css\style.css
│
├── staff\           ← 正規職員に知らせるアドレス
│   ├── default.asp        （part と同じ。staff.asp に飛ばす）
│   ├── staff.asp          職員メニュー
│   ├── entry.asp / tasks.asp     （代理入力用。part と同じもの）
│   ├── daily.asp          日報の作成・確定
│   ├── report.asp         帳票（画面表示）
│   ├── printpdf.asp       帳票（PDF 出力）
│   ├── summary.asp        週の集計表
│   ├── check.asp          入力もれチェック
│   ├── master.asp         マスタ保守
│   ├── error.asp / setup_check.asp / probe*.asp / web.config
│   ├── include\  ／  css\
│
└── data\            ← データベース置き場
    ├── 日報集計_be.accdb
    └── web.config         （何も配信しない設定）
```

**`include` と `css` は part / staff の両方に同じものを置くこと。**
IIS は既定で `#include file="../include/db.asp"` のような
**親フォルダ参照（`..`）を禁止**しています（Enable Parent Paths = False）。
これを True にするのはサーバー全体の設定変更にあたるので避けます。

`data\web.config` は次の内容にして、URL から `.accdb` を取られないようにします。

```xml
<configuration><system.webServer><security><requestFiltering>
  <fileExtensions allowUnlisted="false" />
</requestFiltering></security>
<directoryBrowse enabled="false" />
</system.webServer></configuration>
```

### 役割の切り替えかた

`include\config.asp` に 1 行だけ持たせます。

```vbscript
Const ROLE = "part"    ' part フォルダ用
Const ROLE = "staff"   ' staff フォルダ用
```

`include\auth.asp` の `IsStaff()` がこれを見て判断し、
職員専用ページの先頭で `RequireStaff` を呼んで止めます。
`ROLE` が空のときだけ、`M_担当者.[ログオン名]` を引いて判定する経路を残しておくこと
（将来 Windows 認証に切り替えたくなったとき用）。

### 設定は 1 ファイルにまとめる

**更新のたびに現地の設定を上書きしてしまわないよう、
環境に依存する値は `include\config.asp` だけに置いてください。**

```vbscript
Const DB_PATH       = "/nippou/data/日報集計_be.accdb"  ' サイト先頭 / からの場所でよい
Const ROLE          = "part"
Const PDF_ENGINE    = "edge"
Const PDF_EDGE_EXE  = "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe"
Const APP_NAME      = "電話応対日報 集計システム"
Const PDF_TIMEOUT   = 60
Const PDF_KEEP_HOURS = 24
```

`DB_PATH` は次の 3 通りすべてを受け付けること（利用者が一番書き間違えるところです）。

- `\\サーバー名\共有\日報\xxx.accdb`（UNC）→ そのまま使う
- `D:\data\xxx.accdb`（ドライブ文字）→ そのまま使う
- `/nippou/data/xxx.accdb` や `xxx.accdb` → `Server.MapPath` で解決する

## 6. 帳票（A4 縦 1 枚）の体裁

現行の `日報集計印刷用フォーム.xlsm ＞ 印刷用` シートを再現します。
上から順に：

1. 右上に `【課内限り】`、その下に和暦の日付（`令和 8年 8月25日（火）`）
2. 中央に表題 `電話応対報告書日報集計表`
3. **出勤者の表**：左 3 列に「出勤者 / ○ / 名」を `rowspan="8"` で結合、
   右に「氏名」2 列 ＋「備考」。氏名は 2 列 × 7 行 ＝ 最大 14 名
4. `（ 5 回線 ）`
5. **問合せ件数の表**：左に合計を大きく、右に 申込／抽選／払込用紙／商品発送／その他 の 5 列。
   各セルは「大きい数字」の下に `(職員受電数)` を小さく添える
6. `内　交換 ○ 件 ／ 内　返金 ○ 件`（右寄せ）
7. **記述欄 3 つ**：特記事項 ／ 職員に代わった案件（概要）／ 要望
8. **電話対応以外の業務**：左 8 行 × 右 5 行 の 2 段組（①〜⑬）

### 罫線の注意

**表の罫線は必ず閉じること。**
「出勤者がいない行」「業務項目が無い行」も、空セルではなく
`&nbsp;` を入れた `<td>` にして、枠が途切れないようにしてください。
`tbody tr:last-child td { border-bottom: 0 }` のような
一般化した CSS を書くと帳票側にも効いてしまい、下辺が消えます。
画面用の CSS は必ずクラス（例 `.tw`）で囲ってから当ててください。

### 印刷

- 画面表示（`report.asp`）と PDF（`printpdf.asp`）は
  **同じ関数（`include\sheet.asp` の `SheetHtml(dt)`）を呼ぶこと。**
  片方だけ直して食い違う事故を構造的に防ぎます。
- PDF はサーバーの Edge をヘッドレスで呼びます。

```
msedge.exe --headless=new --disable-gpu --no-pdf-header-footer
           --print-to-pdf="<出力先>" "file:///<入力HTML>"
```

- 作った PDF は一時フォルダに置き、`PDF_KEEP_HOURS` を過ぎたものを毎回掃除すること。

## 7. 必ず踏む地雷（先に知っておくこと）

ここは実際に現地で 1 つずつ踏んだものです。**最初から避けてください。**

### 7-1. `web.config` に書けない設定がある（HTTP 500.19 になる）

IIS は既定で、次を `web.config` から変更することを**禁止**しています。
書くと **サイト全体が HTTP 500.19（構成データが無効です）になり、全ページが開けなくなります。**

- `<system.webServer><asp>` … ASP の設定すべて
- `<security><authentication>` … 匿名認証・Windows 認証
- `<security><ipSecurity>` … IP アドレス制限

**これらは IIS マネージャーの画面から設定する**こととし、
手順書にはスクリーンショットの代わりに「どのアイコンを開くか」を文章で書いてください。

### 7-2. `Response.End` が効かないことがある

VBScript の `Response.End` は**トラップ可能な例外として実装**されています。
そのため、**同じプロシージャ、あるいは呼び出し元で `On Error Resume Next` が生きていると、
`Response.End` はページを止めません。**
「権限がないので止めたつもり」が止まらず、そのまま職員画面が表示されます。

対策：

```vbscript
Sub DbFatal(what, detail)
    On Error Resume Next
    Response.Clear
    On Error GoTo 0           ' ← ここで戻す。これが無いと下の Response.End が効かない
    Response.Write "..."
    Response.End
End Sub
```

**`Response.End` / 権限チェック / 致命エラー表示を呼ぶ箇所が
`On Error Resume Next` の中に入っていないか、機械的に検査するツールを作ってください。**

### 7-3. 自前のエラー画面が IIS に差し替えられる

自前のエラー画面を HTTP 500 で返すと、IIS が本文を捨てて
既定の「An error occurred on the server」に差し替えます。

- 自前のエラー説明は **HTTP 200 で返す**
- `<httpErrors existingResponse="PassThrough">` にする
- ASP の実行時エラーは **500.100**。`500` ではなく `500.100` を拾う

```xml
<httpErrors errorMode="Custom" existingResponse="PassThrough">
  <remove statusCode="500" subStatusCode="100" />
  <error statusCode="500" subStatusCode="100"
         path="/nippou/part/error.asp" responseMode="ExecuteURL" />
</httpErrors>
```

`Server.GetLastError()` は **この設定で呼ばれたエラーページの中でだけ**中身を返します。
エラー画面には **ファイル名／行番号／内容／種別／URL の 5 行**を出し、
「この 5 行をそのままお知らせください」と添えてください。
これがあると、現地とのやりとりが 1 往復で済みます。

### 7-4. `Session` に頼らない

`Session.CodePage` を使うと、セッションが無効な環境で落ちます。
各ページの先頭で次のようにしてください。

```asp
<%@ LANGUAGE="VBScript" CODEPAGE="65001" %>
<% Response.CharSet = "utf-8" : Response.CodePage = 65001 %>
```

### 7-5. テキストファイルの読み込みは `ADODB.Stream` で

`FileSystemObject.OpenTextFile(path, 1, False, -1)` の `-1` は **UTF-16** です。
UTF-8 のファイル（CSS など）を読むと文字化けします。

```vbscript
Function ReadTextUtf8(path)
    Dim st : Set st = Server.CreateObject("ADODB.Stream")
    st.Type = 2 : st.Charset = "utf-8" : st.Open
    st.LoadFromFile path : ReadTextUtf8 = st.ReadText : st.Close
End Function
```

### 7-6. VBScript の配列は上限の添字で宣言する

`Dim a(7)` は **要素 8 個（0〜7）** です。
`Dim a(4)` にして `For i = 0 To 7` で回すと、実行時に
`添字が有効範囲にありません` で全ページが落ちます。
**配列宣言とループ範囲が合っているかを機械的に検査してください。**

### 7-7. 文字コードと改行

| 種類 | 文字コード | 改行 |
|---|---|---|
| `.asp` `.html` `.css` `.md` | UTF-8（**BOM なし**） | LF でよい |
| `.txt`（手順書）`.vbs` `.bas` | **CP932（Shift_JIS）** | **CRLF** |
| `web.config` | UTF-8（BOM なし） | CRLF |

- `.asp` に BOM が付くと、`<%@ LANGUAGE %>` より前に出力が発生して落ちます。
- `.txt` を UTF-8 にすると、利用者がメモ帳で開いたときに文字化けします。
- zip のファイル名は **UTF-8 フラグ（0x800）を立てる**こと。
  立てないと Windows のエクスプローラーで日本語ファイル名が化けます。

### 7-8. SQL は必ずパラメータで渡す

文字列連結で SQL を組み立てないでください。
`ADODB.Command` にパラメータを渡す形に統一し、
ヘルパ関数（`DbQuery(sql, args)` / `DbExec(sql, args)` / `DbScalar(sql, args, 既定値)`）を
1 か所に作ってすべてそこを通してください。

## 8. 現地で動かないときの切り分け（必ず作ること）

設置するのは IT 担当者ではありません。

### `setup_check.asp`

## 9. 検証（Windows / Access / IIS が無い環境で作る前提）

あなたの作業環境に Windows も Access も IIS も無いものとして、
**それでも品質を担保できる検査プログラムを自分で作ってから**コードを書いてください。
「たぶん動く」で納品しないための仕掛けです。

1. **`.accdb` を Windows なしで生成する**
   Java の Jackcess（4.0.5）で `.accdb` を作れます。
   DDL と初期データを 1 本のスクリプトから流し込み、
   **ファイル形式バイト（0x14 が `0x02`）を必ず検査**してください。
2. **SQL を実際に実行して確かめる**
   UCanAccess（5.0.1）＋ HSQLDB で、生成した `.accdb` に対して
   `sql.asp` に書いた SQL を 1 本ずつ実行し、
   **期待値（例：合計 20／申込 12／うち職員 2／出勤者数 3）と突き合わせる**テストを書く。
3. **ASP の静的検査**
   次を機械的に検査するスクリプトを作ること。
   - `<% %>` の対応
   - `#include` 先のファイルが実在するか
   - 定義されていない関数の呼び出し
   - 配列の添字あふれ（7-6）
   - `If` / `For` / `Do` / `Select` の対応
   - `Response.End` 系が `On Error Resume Next` の中で呼ばれていないか（7-2）
4. **帳票の見た目を HTML に起こす**
   `sheet.asp` の文字列組み立て部分を読み取って HTML に変換し、
   ブラウザで罫線と桁が確認できるようにする
   （HTML を検査側に書き写すと本体とズレるので、**必ず読み取って変換**すること）。
5. **納品物の検査**
   zip を作る前に、全ファイルの文字コード・改行・制御文字混入・
   `.accdb` の形式バイトを検査し、1 つでも引っかかったら zip を作らないこと。

```

    └── データベース設計.md
```

### 手順書の書き方

- **1 手順 1 行**。「〜を開きます」「〜をクリックします」の形
- クリックする場所は、画面の文言をそのまま `「 」` で囲んで書く
- 「できたことの確認方法」を各手順の最後に必ず書く
  （例：「ここまでで `http://サーバー名/nippou/part/` を開くと、
  青い帯と『受付入力』のボタンが出ます」）
- うまくいかないときの行き先を書く（→ `setup_check.asp` を開く）

### 更新を渡すときの決まり

**2 回目以降は、全ファイルではなく「変わったファイルだけ」を渡してください。**
そのとき必ず、**どのフォルダに置くか**を表にして添えること。

```
nippou\part\error.asp
nippou\part\web.config
nippou\staff\error.asp
nippou\staff\web.config
```

part 用と staff 用で中身が違うファイルがあるときは、
**「取り違えると何が起きるか」まで書く**こと。

## 11. 守ってほしい進め方

1. **先に検査の仕掛けを作る**（9 章）。コードを書くのはそのあと。
2. **1 つ直したら必ず全部の検査を通す。** 通らないものは渡さない。
3. **推測で「動くはずです」と書かない。**
   確かめていないことは「確かめていません」と書く。
4. **現地で出たエラーは、原因が確定するまで対症療法をしない。**
   まず**原因が画面に出るようにする**（7-3）。
5. **利用者に IIS の設定変更をお願いする前に、
   設定変更なしで解決する方法が無いかを先に考える。**
6. コード内のコメントは、**「何をしているか」ではなく「なぜそうしたか」**を書く。
   とくに上の 7 章にあたる箇所は、理由を書き残さないと次の人が必ず元に戻します。
