# 現行マクロの調査結果と、不具合の原因

対象: `tukauyatu.zip`（記入用フォーム 18 本 / 日報集計印刷用フォーム / 集計表 2 本）

---

## 1. 現行システムの全体像

### ファイルと役割

| ファイル | 役割 |
|---|---|
| `001髙嶋 〜 018鈴木智 / 100顧客Ｇ 記入用フォーム.xlsm` | パート職員・職員が当日の受付を入力する。18 本 |
| `日報集計管理用フォーム.xlsm`（共有・今回未提供） | 全記入用フォームの見出しの「原本」。出勤者・回線数・日付もここが持つ |
| `日報集計印刷用フォーム(前営業日）.xlsm` | 日報の帳票。`更新()` と `印刷()` を持つ |
| `集計表（ＶＢＡ版）.xlsm` | 週次の集計表。`転記()` を持つ |

### 記入用フォームの中身

- **Sheet1**＝入力画面（`A1:N70`）。見出し（製品名・区分名）は
  `=IF([1]集計用フォーム!A6="","",[1]集計用フォーム!A6)` の形で
  `日報集計管理用フォーム.xlsm` への**外部リンク**になっている。
  オペレータが数字を入れるのは `C6:M28` ほか。
- **Sheet2**＝転記用の中間シート（`A1:BP52`）。ここが実質のデータ変換層。

| Sheet2 | 意味 |
|---|---|
| `A1` | 担当者名 = `Sheet1!B1`（**姓だけ**） |
| `A2` | 日付 = `Sheet1!K1` = `=TODAY()` |
| 2 行目 | **集計表データシートの列番号**（3〜8） |
| 3 行目 | 集計表に書き込む備考名（＝区分名） |
| `A4:A52` | 製品名（`Sheet1!A6:A28` と `A32:A52`、末尾 5 行は「その他」固定） |
| 本体 | 件数 |

### 入力画面のブロック構成

| ブロック | Sheet1 の場所 | 区分 |
|---|---|---|
| 区分（製品別） | 行 6〜28 × 列 C〜M | 申込関係／受注／抽選結果／払込用紙 4 種／入金関係／商品発送照会 2 種／製品交換 |
| その他（製品別） | 行 32〜52 × 列 C〜M | 販売予定／製品内容／在庫照会／価格照会 |
| 顧客情報 | 行 54 | ＤＭ停止 5 種／ＤＭ再開／ＤＭ確認／住所変更／新規登録／資料送付／購入履歴 |
| イベント関係 | 行 56 | お金と切手／宇佐神宮／桜の通り抜け ほか 11 種 |
| その他のその他① | 行 58 | オンライン登録／クレジット ほか 11 種 |
| その他のその他② | 行 60 | 返品／返金／貨幣ｾｯﾄ処分関係 ほか |
| 特殊な問合せ | 行 62〜63 | 別添のとおり／下記のとおり（別添不要） |

### 3 つのマクロ

```
更新()   日報集計印刷用フォーム
  ① 日報集計管理用フォーム.xlsm!Worksheets(2) から W2 / F10:O16 / C16 を 印刷用シート へ
  ② 日報入力フォーム\*.xlsm を 電話オペレータデータ\ へコピー
  ③ 元の記入用フォームの入力欄をクリアして上書き保存

印刷()   電話オペレータデータ内の全ファイルを開き、条件付き書式と背景色を消して印刷

転記()   集計表（ＶＢＡ版）
  電話オペレータデータ内の各ファイル Sheet2 を 49 行 × 67 列 走査し、
  0 でないセルを「データ」シートに 1 件 1 行で追記
```

### 数値の流れが 2 本ある

```
記入用フォーム Sheet1
   ├─→ Sheet2 ──転記()──→ 集計表 データシート ──SUMIF──→ 週次の数値
   └─→ 集計用フォーム（18 ファイルを外部リンクで合算）──→ 印刷用シート ──→ 日報の数値
```

**この 2 本が独立している**ことが、すべての「数値が合わない」の根っこです。

## 2. 「特定の方のファイルが吸い出せない」の原因

### 2-1. 担当者名（`Sheet1!B1`）の設定ミス ― これが主因

`転記()` は `wsDate.Cells(k, 11).Value = .Range("A1").Value` として、
Sheet2 の `A1`（＝`Sheet1!B1`）をそのまま担当者名にします。
18 ファイル全部を機械的に調べた結果:

| ファイル | `Sheet1!B1` | 集計表に出る名前 |
|---|---|---|
| `002堀記入用フォーム.xlsm` | **顧客G** | 顧客G |
| `004谷口記入用フォーム.xlsm` | **顧客G** | 顧客G |
| `006国森記入用フォーム.xlsm` | **顧客G** | 顧客G |
| `009西岡記入用フォーム.xlsm` | **顧客G** | 顧客G |
| `015鈴木記入用フォーム.xlsm` | **顧客G** | 顧客G |
| `014福島記入用フォーム.xlsm` | **髙橋** | 髙橋（＝012 の人に合算） |

実際、`集計表（ＶＢＡ版）.xlsm` の担当者列を数えると:

```
石原 45行 / 石井 42行 / 三原 32行 / 髙橋 31行 / 鈴木 29行 / 寺本 28行
髙嶋 24行 / 山口 23行 / 逢坂 22行 / 顧客G 17行 / 小澤 13行
```

**堀・谷口・国森・西岡・福島・鈴木智 は 1 行も出てきません。**
マクロは正常に動いていて、指示どおり `B1` を読んでいるだけなので、
エラーも警告も出ません。これが「吸い出せない」の正体です。

### 2-2. `005三宅記入用フォーム.xlsm` が存在しない

`日報集計印刷用フォーム` は `externalLink9` で
`…\電話オペレータデータ\005三宅記入用フォーム.xlsm` を参照していますが、
配布フォルダにファイルがありません。三宅さんの分は永久に集計されません。

### 2-3. `Range` の修飾漏れ（いつ再発してもおかしくない）

`更新()` / `印刷()` の中身:

```vba
With .Worksheets(1)
    If Range("n70") > 0 Then      ' ← ドットが無い
        ActiveSheet.Unprotect      ' ← ActiveSheet
```

`With .Worksheets(1)` の中なのにドットが無いため、`Range("n70")` は
**`ActiveSheet` の N70** を見ます。今はたまたま全ファイルが Sheet1 を
表示した状態で保存されているので動いていますが、誰か 1 人が
**Sheet2 を開いたまま保存した瞬間、そのファイルは丸ごとスキップされます**
（Sheet2 の N70 は空 → 0 → 未入力扱い）。

### 2-4. `On Error Resume Next` が全部のエラーを握り潰す

`転記()` の先頭に `On Error Resume Next` があります。
ファイルが開けない、値がエラー値、型が合わない ―― どれが起きても
無言でその行を飛ばします。**「エラーが出ないのにデータが無い」**状態は
これで作られます。

### 2-5. 外部リンクの向きがファイルごとに違う

記入用フォームは `[1]` と `[2]` の 2 本の外部リンクを持ちますが、
その指す先がファイルによって入れ替わっています。

| ファイル | `[1]` の指す先 |
|---|---|
| 004谷口 / 006国森 / 009西岡 / 015鈴木 | `\\mint\販売・顧客サービス課\…`（**旧パス**） |
| その他 | `\\fsx.sales.mint.go.jp\share\…`（新パス） |

旧パス側のファイルは、見出し（製品名・区分名）が更新されません。

## 3. 「数値が合わない・正しく転記されない」の原因

### 3-1. `SUMIF` の範囲が行ごとにバラバラ

`集計表（ＶＢＡ版）.xlsm` の 2〜6 行目（週の 5 日分）:

| 行 | 数式の範囲 |
|---|---|
| 2 行目（月） | `$A$8:$J$383` |
| 3 行目（火） | `$A$8:$J$383` |
| 4 行目（水） | `$A$8:$J$935` |
| 5 行目（木） | `$A$8:$J$935` |
| 6 行目（金） | `$A$8:$J$428` |

データが 383 行を超えた時点で、**月曜と火曜の合計だけが過少**になります。
実際のデータは 379 行あり、あと数行で境界を越えるところでした。

### 3-2. 集計表がクリアされない

`転記()` は `k = wsDate.Cells(Rows.Count, 1).End(xlUp).Row + 1` で
**追記するだけ**です。`集計表（ＶＢＡ版）.xlsm` には
8/17〜8/21（前週）と 8/24〜8/25（当週）が混在していました。
週をまたぐと二重計上になります。

### 3-3. 日付が `=TODAY()` で揮発する

`Sheet2!A2` = `Sheet1!K1` = `=TODAY()` です。
`更新()` / `転記()` は計算モードを手動にしてから開くので普段は保たれますが、
**誰かがそのファイルを普通に開いた瞬間、日付が開いた日に書き換わります**。
過去日のデータが当日に付け替わる事故が起こり得ます。

### 3-4. 転記される区分名が入力画面とズレている

`Sheet2` の 3 行目（集計表に書く名前）はハードコードされていて、
外部リンク経由で更新される入力画面の見出しと同期していません。

| 入力画面の見出し | 集計表に書かれる名前 |
|---|---|
| 宇佐神宮 | イベント関係（造幣局 ＩＮ） |
| 佐伯区民まつり | イベント関係（名古屋貨幣まつり） |
| アンケート | イベント関係（予備） |
| 金工品懇談会 | **桜サポート** |
| 金工品Ｇ関係 | 金工品Ｇへ電話転送 |
| 広報（工場見学含む） | 広報室（工場見学含む） |

さらに「その他」ブロックの G〜I 列（内容問合せ／組込みミス交換／その他交換）は、
**入力画面側に見出しが無い**（オペレータが入力できない）のに転記対象になっています。

## 4. 「フォントサイズが勝手に変わる」の原因

記入用フォーム Sheet1 を調べると:

- **「縮小して全体を表示する」(shrinkToFit) が 67 セル**
- **結合セルが 76 か所**
- 条件付き書式は **0 件**

「縮小して全体を表示する」は、セル幅に収まらない文字を**表示上だけ自動で縮める**
機能です。結合セルと組み合わさると縮小の基準が直感と合わず、
「勝手にサイズが変わった」ように見えます。フォント設定自体は変わっていません。

なお `印刷()` の `Cells.FormatConditions.Delete` は、条件付き書式が 0 件なので
何もしていません（そして修飾漏れで `ActiveSheet` に対して実行されます）。

## 5. Access 版でどう解決されるか

| 現行の問題 | Access 版での扱い |
|---|---|
| 担当者名が `B1` セルの文字列 | `M_担当者` マスタの外部キー。名前の打ち間違いという概念が無い |
| ファイルが無い人は集計されない | 「入力もれチェック」画面が、出勤登録があって実績が無い人を毎日出す |
| 数値の経路が 2 本 | `T_受電` 1 本。日報も集計表も同じクエリから作る |
| `SUMIF` の範囲がバラバラ | `GROUP BY` なので範囲という概念が無い |
| 追記のみで二重計上 | `UNIQUE(対象日, 担当者ID, 区分ID, 製品ID)` で二重登録できない |
| `=TODAY()` で日付が動く | `対象日` は入力時に確定して保存される |
| 転記名と入力画面名のズレ | 同じ `M_区分.区分名` を両方で使う。旧名は `旧転記名` に残して移行照合に使う |
| 縮小して全体を表示 | 帳票は Access レポート。セルという概念が無い |
| ファイルを開いたまま保存でスキップ | ファイルを開かない |
