# Web 版（ASP + Access）

Access ファイルをそのまま DB として使う、イントラネット用の Web サイトです。
デスクトップ版 Access と**同じ `.accdb` を見る**ので、どちらから入力しても同じデータになります。

> 現時点ではモックアップです。実運用に載せる前に、下の「本番前に必要なこと」を必ず読んでください。

---

## なぜ Classic ASP か

- Access（ACE OLEDB）と組み合わせる構成として枯れていて、追加のランタイムが要らない
- IIS の既定機能だけで動く（ASP.NET のインストールや .NET のバージョン管理が不要）
- 1 ファイル 1 画面で読めるので、担当者が代わっても追いやすい

将来 SQL Server に移す場合、変更が要るのは `include/db.asp` の接続文字列だけになるよう、
SQL はすべてパラメータ渡しで書いてあります。

---

## 役割で画面を分けている

入力する人と、まとめる人が違うので、**画面そのものを分けています**。

| 役割 | 入口 | 使える画面 |
|---|---|---|
| パート職員 | `default.asp` | 受付入力・その他業務 |
| 職員 | `staff.asp` | 上に加えて 日報・帳票印刷・集計表・入力もれ・マスタ保守 |

決めているのは `include/auth.asp` の 1 行だけです。

```vbscript
Const STAFF_USERS = ""      ' 空 = 全員が職員（導入直後の既定）
Const STAFF_USERS = "t-okada,y-fujita"   ' この 2 人だけが職員
```

- 職員用の画面は先頭で `RequireStaff` を呼び、パート職員なら**その場で止めます**。
  メニューから消すだけでなく、URL を直接打っても開けません。
- ヘッダのメニューも役割で入れ替わります。押せない画面は最初から並びません。
- 職員のメニューには「パート職員の画面」も置いてあります。
  お休みの日に職員が代わりに入力できます。

> **導入直後は `STAFF_USERS` が空**なので、全員が職員として全画面を使えます。
> 運用を始める前に、職員のかたのログオン名を入れてください。

### Access の保存クエリを使わない

SQL は Access 側の保存クエリ（`Q_…`）ではなく、**`include/sql.asp` が持っています**。
理由は 2 つあります。

1. **Access を 1 台も使わずに `.accdb` を配れるようにするため。**
   納品する `日報集計_be.accdb` は `tools/gen_accdb.py`（Jackcess）が作っており、
   表・マスタ・つながりは作れますが、保存クエリは作れません。
2. **ACE では Access 専用の関数が使えないため。**
   とくに `Nz()` は Web から呼ぶと「関数 'Nz' が定義されていません」で失敗します。
   Access の中では動くのに Web からだけ落ちる、という分かりにくい形を避けています。

`include/sql.asp` は **`src/modSetupQuery.bas` から自動生成**しています
（`tools/gen_sql_asp.py`）。Access 版と Web 版で SQL がずれることはありません。
生成時に次の 3 つを機械的に行っています。

- 末尾の `ORDER BY` と `;` を外す（副問い合わせとして埋め込むため）
- `Nz(x,0)` を `IIf(IsNull(x),0,x)` に置き換える
- クエリの中の `[Q_…]` を、その中身に展開する（入れ子の解決）

呼ぶ側はこう書きます。並び順は呼ぶ側で付けます。

```vbscript
Set rs = DbQuery("SELECT * FROM (" & SQL_未入力チェック() & ") AS C " & _
                 "WHERE C.[対象日]=? ORDER BY C.[表示順]", Array(dt))
```

この SQL は、Windows が無くても `tools/test_sql.py` で実際に流して確かめられます
（UCanAccess で `.accdb` に接続し、日報の集計値が手計算と合うかまで見ています）。

### 印刷は PDF で出す

「印刷する」を押すと、**サーバーが PDF を作って別のタブに開きます**。
利用者はいつもどおり PDF を印刷するだけです。

なぜ一手間かけるかというと、ブラウザの印刷は既定で紙の上下に
**日付と URL とページ番号**を入れるからです。これは CSS では消せず、
利用者が印刷設定を毎回変えるしかありません。
課内限りの回覧文書なので、そこを設定任せにしていません。

```
report.asp ─「PDF で印刷する」→ printpdf.asp
                                  ├ include/sheet.asp で帳票の HTML を作る
                                  ├ include/pdf.asp で PDF に変換（Edge を裏で起動）
                                  ├ ブラウザに送る（Content-Disposition: inline）
                                  └ サーバー上のファイルは送った直後に消す
```

- **PDF はサーバーに溜まりません。**送った直後に消します。
  それでも消し残ったものは、次に誰かが印刷したときに掃除します（既定 24 時間）。
- 変換できない環境のために、「ブラウザで印刷する」も残してあります。
  そのときだけ、印刷設定で「ヘッダーとフッター」を外してください。
- 変換に失敗したときは、白紙ではなく**理由を書いた画面**が出ます。

帳票そのものは **A4 縦 1 枚**に収まるよう調整してあります。

| 項目 | 値 |
|---|---|
| 用紙 | A4 縦 |
| 余白 | 12mm（`@page` で指定済み） |
| 倍率 | 等倍（「用紙に合わせる」は不要） |
| 実測 | 内容 241mm ／ 使える高さ 273mm（余り 32mm） |

画面から印刷したときは `@media print` でヘッダ・ナビ・フッタ・印刷バーが消え、
帳票だけが出ます。記述欄（特記事項など）に長文を入れると伸びるので、
その場合は 2 枚目に送られます。

現行 Excel の印刷用シートは ＭＳ 明朝 9pt が基調だったので、
帳票の本文も 9.5pt に合わせています。10.5pt だと項目名が折り返して 1 枚に収まりません。

> 帳票の中身を直すときは `include/sheet.asp` **だけ**を直してください。
> 画面と PDF が同じ関数を呼んでいるので、片方だけ変わることがありません。

### マスタの削除について

`master.asp` の削除は、実績から参照されていないマスタだけを消します。
参照されているものは `UsageCount` が拒否し、「有効を外してください」と案内します。

```
削除ボタン → UsageCount(kind, id) → 0 件なら DELETE
                                  → 1 件以上なら拒否して理由を表示
```

Access 側（`modApp.App_Delete`）も同じ規則で止めます。
どちらも通り抜けた場合はテーブル間の参照整合性が最後の砦になるので、
実績のあるマスタが消えることはありません。

## IIS への配置

### 1. 前提を入れる

- IIS の「ASP」機能を有効化
  （サーバー マネージャー → 役割と機能 → Web サーバー → アプリケーション開発 → ASP）
- **Microsoft Access Database Engine 2016 Redistributable** を入れる
- **アプリケーションプールのビット数を ACE と合わせる**
  （64 bit の ACE を入れたなら「32 ビット アプリケーションの有効化」は `False`）

### 2. 置く

```
C:\inetpub\wwwroot\nippou\      ← web/ の中身をそのまま
D:\nippou\data\日報集計_be.accdb ← バックエンド
```

### 3. 権限

`.accdb` を置いた**フォルダ**に、アプリケーションプール ID
（既定は `IIS AppPool\<プール名>`）の**変更権限**を与えます。
読み取りだけでは足りません ―― ACE がロックファイル `.laccdb` を
同じフォルダに作るためです。

### 4. 設定

`include/db.asp` の先頭:

```vbscript
Const DB_PATH = "D:\nippou\data\日報集計_be.accdb"
```

### 5. 文字コード

各 `.asp` は **UTF-8（BOM なし）** で保存されています。
先頭の `<%@ CODEPAGE="65001" %>` と `Response.CharSet = "utf-8"` が対になっているので、
**編集時に Shift_JIS で保存し直さないでください**（文字化けします）。

## 本番前に必要なこと

モックアップの段階で意図的に入れていないものです。運用前に必ず対応してください。

| 項目 | 内容 |
|---|---|
| **認証** | `web.config` で Windows 認証を有効・匿名認証を無効にしてあります。IIS 側でも同じ設定になっているか確認してください。ログオン名は `T_受電.登録者` に記録されます |
| **職員の指定** | `include/auth.asp` の `STAFF_USERS` に、職員のかたのログオン名を並べます。**空のままだと全員が職員扱いです。**運用開始前に必ず設定してください |
| **PDF 変換** | `include/pdf.asp` の `PDF_EDGE_EXE` がサーバーの Edge の場所と合っているか確認してください。Edge が無い環境では `PDF_ENGINE` を `"wkhtmltopdf"` にします。作業用フォルダ（既定は Windows の一時フォルダ）に、アプリケーションプール ID の変更権限が要ります |
| **CSRF 対策** | 更新は POST 限定にしてありますが、トークン検証は入れていません。Windows 認証 ＋ イントラ限定を前提にしています |
| **同時実行** | Access/ACE は数十人規模までです。それを超えるなら SQL Server Express への移行を検討してください |
| **エラー画面** | 現状は IIS の既定エラーが出ます。詳細エラーを外部に出さない設定にしてください |
| **バックアップ** | Web 経由でも書き込むので、バックエンドのバックアップはデスクトップ版と同様に必須です |

### SQL インジェクションについて

画面から来た値を文字列連結で SQL に埋めている箇所はありません。
すべて `DbQuery` / `DbExec` のパラメータ経由です。
新しい画面を足すときも、この 2 つ以外で SQL を組まないでください。

```vbscript
' 良い
DbExec "UPDATE [T_受電] SET [件数]=? WHERE [受電ID]=?", Array(cnt, rowId)

' 駄目
gConn.Execute "UPDATE [T_受電] SET [件数]=" & cnt & " WHERE [受電ID]=" & rowId
```

## デスクトップ版と Web 版の使い分け

| | デスクトップ Access | Web (ASP) |
|---|---|---|
| 各 PC への導入 | フロントエンド `.accdb` の配布が要る | ブラウザだけ |
| 印刷 | Access レポート。最も確実 | サーバーで PDF を作って開く（A4 縦 1 枚。日付や URL は入らない） |
| 速度 | 速い | 共有フォルダ越しの ACE 接続なので Access より遅い |
| 保守 | 各 PC のフロントエンド更新が要る | サーバー 1 か所を直せば全員に反映 |
| 導入のハードル | 低い（サーバー不要） | IIS の設置許可が要る |

**当面はデスクトップ版で運用し、Web 版は評価・並行稼働**という進め方を想定しています。
どちらも同じバックエンドを見るので、混在させても数値は一致します。
