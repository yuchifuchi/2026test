# データベース設計

## 設計の芯

**受付の記録は `T_受電` にしか無い。** 日報も集計表も帳票も、すべてそこから作る。
現行 Excel のように「集計用フォームの SUM」と「集計表の SUMIF」という
2 本の経路を持たせない ―― これだけで「数値が合わない」は構造的に消えます。

```
                    ┌─→ Q_日報_受電 ──→ R_日報 / report.asp     (日報)
T_受電 ──┬─────────┤
         │          └─→ Q_週次集計  ──→ R_集計表 / summary.asp  (集計表)
         └─→ Q_受電明細 ─────────────→ 明細一覧
```

## テーブル

### マスタ

| テーブル | 主キー | 内容 |
|---|---|---|
| `M_集計列` | 集計列ID (3〜8) | 申込方法 / 抽選結果 / 納付書発送 / 商品発送 / その他 / 商品交換 |
| `M_ブロック` | ブロックID (0〜7) | 入力画面のブロック。0 =（なし） |
| `M_製品` | 製品ID | 製品名。**0 =「（製品指定なし）」を必ず持つ** |
| `M_区分` | 区分ID | 問合せ区分。**どの集計列に積むか**を持つ |
| `M_担当者` | 担当者ID | 在籍期間つき |
| `M_業務項目` | 業務項目ID | 電話応対以外の業務 ①〜⑬ |

#### `M_担当者` ― 職員の入れ替わりに耐える形

```
担当者ID     LONG  PK
担当者コード TEXT(10)      席番号。再利用されるので UNIQUE にしない
姓 / 名 / 氏名 / カナ
職員区分     TEXT(10)      'パート' | '職員'   ← 帳票の「（）内は職員受電数」に使う
在籍開始日   DATETIME      NULL = 昔から在籍
在籍終了日   DATETIME      NULL = 在籍中
表示順       LONG
有効         BIT
備考         MEMO
```

**退職者の行は消しません。** `在籍終了日` を入れると入力画面の候補から
消えますが、過去の日報・集計表はその人の名前のまま残ります。
行を消すと過去の帳票が壊れるので、画面にもその旨を出しています。

#### `M_区分` ― 現行 Sheet2 の 2 行目を表に出したもの

```
区分ID     LONG  PK
ブロックID LONG  → M_ブロック
区分名     TEXT(100)
集計列ID   LONG  → M_集計列    ← 現行 Sheet2 の 2 行目に埋まっていた情報
内訳区分   TEXT(20)            ← 帳票の「内 交換」「内 返金」を引くための印
表示順 / 有効
旧転記名   TEXT(100)           ← 現行 Sheet2 の 3 行目。移行時の照合専用
```

現行では「この区分は集計表の何列目か」が **Sheet2 の 2 行目のセル**に
書かれていて、誰も触れませんでした。ここではマスタ画面から変更できます。

### 実績

| テーブル | 主キー | 制約 |
|---|---|---|
| `T_日報` | 対象日 | 1 日 1 行 |
| `T_出勤` | 出勤ID | `UNIQUE(対象日, 担当者ID)` |
| `T_受電` | 受電ID | `UNIQUE(対象日, 担当者ID, 区分ID, 製品ID)` |
| `T_業務実績` | 実績ID | `UNIQUE(対象日, 担当者ID, 業務項目ID)` |
| `T_取込ログ` | ログID | Excel 取込で引き当てられなかった行 |

```
T_受電
  受電ID     COUNTER PK
  対象日     DATETIME  NOT NULL
  担当者ID   LONG      NOT NULL → M_担当者
  区分ID     LONG      NOT NULL → M_区分
  製品ID     LONG      NOT NULL → M_製品   ※製品を伴わない区分は 0
  件数       LONG      NOT NULL
  備考2 / 備考3
  登録日時 / 更新日時 / 登録者
  UNIQUE(対象日, 担当者ID, 区分ID, 製品ID)
```

`製品ID` を NULL 許容にせず **0 を「製品指定なし」**にしたのは、
Access の UNIQUE 制約が NULL 同士を「別の値」として扱い、
NULL 混じりだと二重登録を防げないためです。

## 帳票欄と集計列の対応

現行 `印刷用` シート 18 行目の数式から復元したものです。

| 帳票の欄 | 集計列 | 現行 Excel の数式 |
|---|---|---|
| 申込 | 3 申込方法 | `集計用フォーム!C29 + D29` |
| 抽選 | 4 抽選結果 | `集計用フォーム!E29` |
| 払込用紙 | 5 納付書発送 | `集計用フォーム!F29`（= `SUM(F6:I28)`） |
| 商品発送 | 6 商品発送 | `集計用フォーム!K29 + L29` |
| その他 | 7 + 8 | `集計用フォーム!J29 + M29 + N60` |
| 内 交換 | 8 商品交換 | `集計用フォーム!M29` |
| 内 返金 | `内訳区分 = '返金'` | `集計用フォーム!D60` |
| （）内 | `職員区分 = '職員'` | `[1]Sheet1!…`（100顧客Ｇファイル） |

> 現行の `U19` は `集計用フォーム!M29 + [2]Sheet1!$M$29`（全体 ＋ 職員）を
> 足していて二重計上に見えますが、`[2]` は死んだ旧パスを指すため実質 0 でした。
> Access 版では全体の集計列 8 だけを出しています。

## 画面と帳票

| 名前 | 内容 |
|---|---|
| `F_メニュー` | 起動画面 |
| `F_日次入力` ＋ `F_日次入力_明細` | 対象日・担当者を選んで件数を入力 |
| `F_業務実績` | 電話応対以外の業務 |
| `F_日報` ＋ `F_日報_出勤` | 出勤者・回線数・記述欄・集計値の確認・確定 |
| `F_集計表` | 期間指定の集計と明細 |
| `F_未入力チェック` | 入力もれ |
| `F_マスタ_担当者` / `_製品` / `_区分` / `_業務項目` | 保守 |
| `R_日報` | 現行「印刷用」シートの体裁を再現した A4 縦 1 枚 |
| `R_集計表` | 期間の日別集計 |
| `R_受電明細` | 明細一覧（A4 横） |

画面と帳票は `modSetupUI` / `modSetupReport` が**コードから組み立てます**。
`.accdb` をバイナリで配らずに済み、Git で差分が追え、作り直しても同じ画面になります。

イベントはすべて `=App_Click("名前")` の式で書き、フォームモジュールを持ちません。
そのため「VBA プロジェクト オブジェクト モデルへのアクセスを信頼する」を
有効にしなくても構築できます。処理の実体は `modApp` にあります。

## マスタの出どころ

`data/*.csv` は現行 Excel から機械的に抽出したものです（`tools/extract_master.py`）。

- 見出し（製品名・区分名）: 記入用フォームの**外部リンクキャッシュ**
  （`xl/externalLinks/externalLinkN.xml`）に残っている
  `日報集計管理用フォーム!集計用フォーム` の値。結合セルは
  記入用フォーム Sheet1 の結合範囲を使って展開している
- 集計列・旧転記名: 記入用フォーム `Sheet2` の 2 行目 / 3 行目
- 担当者: ファイル名と `Sheet1!B1/C1`、`日報集計印刷用フォーム!Sheet1!Q6:Q20` の氏名一覧

現行 Excel の設定ミス（`B1` が別人）は `M_担当者.備考` に移行メモとして残してあり、
マスタ保守画面に表示されます。
