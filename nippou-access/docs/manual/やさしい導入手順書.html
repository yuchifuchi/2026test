電話応対報告書 日報集計

やさしい導入手順書

このシステムを使えるようにするまでの手順です。 パソコンにくわしくない方でも、上から順にそのとおりにやれば終わります。 むずかしい言葉には、そのつど説明をつけました。

全部で 3 つのパート 合わせて 40 分ほど 1 回やれば終わりです

これから何をするのか

このシステムは、3 つの場所に分かれて動きます。 まずは全体の形を見てください。細かいことは分からなくて大丈夫です。

先に、6 つの言葉だけ

この手順書に出てくる、聞きなれない言葉です。ここだけ読んでおけば大丈夫です。

Access（アクセス）
Microsoft の、データをためておくソフトです。Excel の仲間ですが、 たくさんのデータをきちんと管理するのが得意です。 今回は「データの入れ物」としてだけ使います。開いて操作することはありません。
accdb（アクシーディービー）
Access で作られるファイルの種類です。日報集計_be.accdb のように、 名前のうしろに .accdb が付きます。この 1 個がデータの本体です。
サーバー
みんなが使う画面を配る役目のパソコンです。 ふだん誰も前に座らない、置きっぱなしのパソコンだと思ってください。
IIS（アイアイエス）
Windows にもともと入っている、画面を配るためのしくみです。 新しく買う必要はありません。スイッチを入れるだけです。
ブラウザ
インターネットを見るソフトです。Microsoft Edge、Chrome など。 みなさんはこれだけを使います。
共有フォルダ
職場のみんながアクセスできる、ネットワーク上のフォルダです。 \\fsx.sales.mint.go.jp\share\… のような場所のことです。
パート 1

データの置き場所を決める

データベースはもうできています。共有フォルダに移すだけです。

かかる時間：1 分
1
02_データベース_Access のフォルダを開きます

お渡しした一式の中にあります。中に、こういうファイルが入っています。

日報集計_be.accdb

これが「データの入れ物」です

担当者・製品・区分などの一覧まで入った、すぐ使える状態です。 Access は 1 台も要りません。作る作業も、開く必要もありません。 （このファイルには VBA が入っていないので、開いてもマクロの警告は出ません）

2
共有フォルダに移します

日報集計_be.accdb を、職場の共有フォルダにコピーします。 場所はどこでもかまいませんが、次の 2 つを満たす場所にしてください。

・毎日バックアップされるフォルダであること

・みんなが読み書きできること（読み取り専用では動きません）

大事：置いた場所をメモしてください

フォルダのアドレス欄をクリックすると、こういう文字が出ます。これをメモしてください。

\\fsx.sales.mint.go.jp\share\share_電話オペレータ\日報\日報集計_be.accdb

パート 2 の 手順 7 で、この文字をそのまま貼り付けます。

同じフォルダに見慣れないファイルができます

日報集計_be.laccdb というファイルが自動でできます。 誰かが使っている間だけできる目印なので、消さないでください。

パート 2

画面をサーバーに置く

ここがいちばん手数の多いところです。とはいえ、やることは 「スイッチを入れる」「ファイルを置く」「3 か所だけ書き換える」の 3 つです。 サーバーを触れる方（情報システム担当のかた）にお願いしてください。

かかる時間：30 分ほど
3
サーバーのスイッチを 2 つ入れます

Windows のサーバーには、画面を配るしくみ（IIS）が最初から入っています。 使う状態にするだけです。

「サーバー マネージャー」→「役割と機能の追加」と進み、 次の 2 つにチェックを入れます。

  • ASP　… Web サーバー → アプリケーション開発 → の中にあります
  • Windows 認証　… Web サーバー → セキュリティ → の中にあります

「Windows 認証」を入れると、誰が入力したかが自動で記録されます。 利用者がパスワードを打つ必要はありません。

4
Access のデータを読むための部品を入れます

Microsoft Access Database Engine 2016 Redistributable という、 Microsoft が無料で配っているものを入れます。 「Access のデータを読むための部品」だと思ってください。

ここだけは間違えやすいので気をつけてください

入れた部品が 64 ビット版なら、IIS の側も 64 ビットで動かす必要があります。

IIS マネージャーの「アプリケーション プール」で、使うプールを選び、 「詳細設定」→ 「32 ビット アプリケーションの有効化」を False にしてください。

ここが合っていないと、あとで 「Provider が見つかりません」というエラーが出ます。 このエラーが出たら、まずここを疑ってください。

5
ファイルをサーバーに置きます

お渡しした一式の 03_Webサイト_ASP の中にある wwwroot フォルダの中身を、そのままコピーします。

置き場所：C:\inetpub\wwwroot\nippou\

wwwroot というフォルダごとではなく、中身をコピーしてください。 default.asp や css フォルダが直接 nippou の下に並ぶ形が正解です。

ここまでできたか確認

C:\inetpub\wwwroot\nippou\default.asp というファイルがありますか。

6
データを置いたフォルダに、書き込みの許可を出します

パート 1 で 日報集計_be.accdb を置いたフォルダを右クリックし、 「プロパティ」→「セキュリティ」タブ→「編集」と進みます。

「追加」を押して、次の名前を入れます（<プール名> は 手順 4 で見たアプリケーション プールの名前です）。

IIS AppPool\<プール名>

追加できたら、「変更」にチェックを入れて「OK」を押します。

「読み取り」だけでは動きません

Access は、データを読むときに、同じフォルダに小さな作業用ファイル （.laccdb）を作ります。 そのため書き込みの許可が要ります。 ここを「読み取り」だけにすると、あとで 「外部データベースを開けません」というエラーになります。

7
3 か所だけ書き換えます

置いたファイルのうち、include フォルダの中の 3 つを、 メモ帳ではなく 「メモ帳」以外の編集ソフトで開いて直します。

なぜメモ帳ではないのか

古いメモ帳で保存すると、日本語が読めなくなることがあります。 「サクラエディタ」「Visual Studio Code」など、 文字コードを選べる編集ソフトを使い、 UTF-8（BOM なし）のまま保存してください。

1 つめ：include\db.asp

上のほうにある、この行を探します。

Const DB_PATH = "D:\nippou\data\日報集計_be.accdb"

引用符（"）の間を、手順 2 でメモした文字に置き換えます。 引用符そのものは消さないでください。

2 つめ：include\auth.asp

上のほうにある、この行を探します。

Const STAFF_USERS = ""

引用符の間に、最初にマスタ保守を開くかた 1 人のログオン名を入れます。 ドメイン名（\ の前）は書きません。

Const STAFF_USERS = "t-okada"

誰が職員かは、ふだんは画面から決めます

マスタ保守の「担当者一覧」に「ログオン名」の欄があります。 そこに Windows のログオン名を入れて区分を「職員」にすると、 その方に日報・帳票印刷・集計表・入力もれ・マスタ保守が出るようになります。 ファイルを直す必要はありません。
ここ（auth.asp）は、まだ誰も登録していないときの入口として 1 人だけ書いておくためのものです。

誰も登録しないままにしないでください

ログオン名が 1 件も入っていない間は、全員が職員扱いになり、 全部の画面が開けてしまいます。担当者を消したり、区分を変えたりできてしまうので、 設置が済んだらマスタ保守でみなさんのログオン名と区分を入れてください。

3 つめ：include\pdf.asp（日報を PDF で印刷するため）

上のほうにある、この行を探します。

Const PDF_EDGE_EXE = "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe"

サーバーの中で msedge.exe が本当にその場所にあるか、 エクスプローラーで確かめてください。あればそのままで大丈夫です。

なぜ Edge を使うのか

ブラウザでそのまま印刷すると、紙の上下に日付とアドレス（URL）が 勝手に入ります。課内限りの文書なので、 サーバーの中で Edge をこっそり動かして PDF を作り、それを開く形にしました。 作った PDF は送ったらすぐ消すので、たまりません。

パート 3

ちゃんと動くか確かめる

ここまでできたら、実際に開いて確かめます。

かかる時間：5 分
8
ブラウザで開きます

アドレス欄に、次のように打ちます。

http://<サーバーの名前>/nippou/

5 つ確かめてください

1. メニューの画面が出る

2. 画面の右上に自分の名前が出る（「(未認証)」ではない）

3.「受付入力」を開くと、担当者の一覧に名前がずらりと並ぶ

4.「帳票印刷」→「PDF で印刷する」で、別のタブに PDF が開き、A4 縦 1 枚に収まる

5. その PDF の紙面に、日付や URL が入っていない

6. パート職員のかたのパソコンから開くと、上の帯に 「受付入力」と「その他業務」だけが並ぶ

9
みなさんにショートカットを配ります

デスクトップに、手順 8 のアドレスへのショートカットを作って配ります。

パソコンにくわしくない方も多いので、 アドレスを手で打たせない形にしてください。 これだけで問い合わせがぐっと減ります。

10
マニュアルを印刷して配ります

01_マニュアル の 操作マニュアル.html を開き、 「印刷する」を押します。A4 縦 20 ページで出ます。

役割ごとに章が分かれています。 パート職員のかたは 2 章、職員のかたは 3 章、担当者のかたは 4 章だけ読めば足ります。

これで導入は完了です

おつかれさまでした。翌営業日から使い始められます。

うまくいかないとき

「Provider が見つかりません」と出る
手順 4 の部品が入っていないか、ビット数が合っていません。 IIS マネージャーの「アプリケーション プール」→「詳細設定」で 「32 ビット アプリケーションの有効化」を確認してください。 64 ビットの部品を入れたなら False です。
「外部データベースを開けません」と出る
手順 6 の書き込み許可が足りていません。 .accdb を置いたフォルダに「変更」の権限があるか確認してください。 ファイルではなくフォルダです。
画面の文字が「�」のように化ける
手順 7 で、メモ帳などで保存し直したときに文字コードが変わっています。 お渡しした元のファイルに戻し、 文字コードを選べる編集ソフトで UTF-8（BOM なし）のまま保存し直してください。
右上の名前が「(未認証)」になっている
IIS の「匿名認証」が有効なままです。 IIS マネージャーで対象のサイトを選び、「認証」を開いて、 匿名認証を「無効」、Windows 認証を「有効」にしてください。
全員が「マスタ保守」を開けてしまう
マスタ保守の「ログオン名」が 1 件も入っておらず、手順 7 の STAFF_USERS も空のままです。どちらかを入れてください。
担当者の一覧に名前が出ない
その方に「退職日」が入っているか、「有効」のチェックが外れています。 「マスタ保守」→「担当者」で確認してください。
印刷すると 2 枚になる
印刷の設定で倍率が 100% になっていないことがほとんどです。 「用紙に合わせる」のチェックを外してください。 それでも 2 枚になるときは、特記事項の文章が長すぎます。
どうしても分からない
画面を写真に撮って、次の 3 つと一緒に連絡してください。 原因がすぐ分かります。
  • どの手順の番号でつまずいたか
  • 何をしたときに出たか
  • 起きた時刻

もっとくわしく知りたいとき

  • 01_マニュアル … 毎日の使い方（役割ごと）
  • 05_設計資料 … なぜ作り替えたのか、どういう仕組みか
  • 04_モックアップ … 本番と同じ画面を、ブラウザだけで試せます
