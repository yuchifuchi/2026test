# 設置手順（情報システム担当者向け）

構成は次のとおりです。

```
[利用者の PC]                    [Web サーバー (IIS)]              [共有フォルダ]
  ブラウザ        ──HTTP──▶   Classic ASP (web/)   ──ACE──▶   日報集計_be.accdb
                                Windows 認証                      (データ本体)
```

利用者の PC に入れるものは**ありません**。Access も不要です。

---

## 1. データベースを作る

Access が入っている PC で 1 回だけ行います。

1. 空の `.accdb` を作成して開く（ファイル名は `日報集計_be.accdb`）
2. `Alt` + `F11` で VBA の画面を開く
3. **「ファイル」→「ファイルのインポート」** で `dist/` の 7 ファイルを読み込む
   （1 つずつ 7 回。**順番は問いません**）
4. `modSetup` の **`Setup_DBOnly`** にカーソルを置いて `F5`

> **貼り付けではなくインポートを使ってください。**
> `.bas` の 1 行目 `Attribute VB_Name = "modSetup"` は、コピー＆貼り付けすると
> エラーになります（`Attribute` 行は手で入力できないため）。
> インポートならこの行が読まれてモジュール名が自動で付くので、
> 名前を付け直す作業も要りません。

> `Setup_All` ではなく **`Setup_DBOnly`** を使ってください。
> `Setup_All` は Access 単体で運用する場合用で、今回不要なフォームとレポートまで作ります。

できたファイルを `日報集計_be.accdb` にリネームし、共有フォルダに置きます。

過去データの取り込みは、この段階で Access 側から行ってください
（[導入手順](../03_導入手順.md) の手順 4）。

---

## 2. IIS を用意する

### 有効にする機能

- **ASP**（役割と機能 → Web サーバー → アプリケーション開発 → ASP）
- **Windows 認証**（同 → セキュリティ → Windows 認証）

### 追加で入れるもの

- **Microsoft Access Database Engine 2016 Redistributable**

> **アプリケーションプールのビット数を ACE と合わせてください。**
> 64bit の ACE を入れたなら「32 ビット アプリケーションの有効化」は `False` です。
> ここが合っていないと `Provider が見つかりません` というエラーになります。

---

## 3. ファイルを配置する

```
C:\inetpub\wwwroot\nippou\      ← web/ の中身をそのまま
D:\nippou\data\日報集計_be.accdb ← 手順 1 で作ったファイル
```

`web.config` も一緒に置いてください。Windows 認証・既定ページ・
エラー画面・拡張子のブロックがまとめて設定されます。

---

## 4. 権限を与える

`.accdb` を置いた**フォルダ**に、アプリケーションプール ID
（既定は `IIS AppPool\<プール名>`）の**変更権限**を与えます。

> **読み取りだけでは動きません。** ACE がロックファイル `.laccdb` を
> 同じフォルダに作るため、フォルダへの書き込み権限が要ります。

---

## 5. 設定を書き換える

`include/db.asp` の先頭：

```vbscript
Const DB_PATH = "D:\nippou\data\日報集計_be.accdb"
```

`include/auth.asp` の先頭：

```vbscript
' マスタ保守を触れる人のログオン名を「,」区切りで並べる
Const ADMIN_USERS = "t-okada,y-fujita"
```

空のままにすると全員がマスタ保守を触れます。運用開始前に必ず設定してください。

---

## 6. 動作確認

`http://<サーバー名>/nippou/` を開きます。

| 確認すること | 期待する結果 |
|---|---|
| メニューが出る | 当日の件数と入力もれ件数が表示される |
| 右上の名前 | 自分の Windows ログオン名が出る |
| 受付入力 | 担当者の一覧に在籍者が出る |
| 帳票プレビュー → 印刷 | A4 縦 1 枚に収まる |
| 一般ユーザーでマスタ保守 | 「この画面は担当者だけが開けます」と出る |

---

## 7. 利用者に配る

デスクトップに `http://<サーバー名>/nippou/` へのショートカットを配布してください。
ITに不慣れな方が多いため、**アドレスを手で打たせない**ことが大事です。

---

## 運用時の注意

### 文字コード

`.asp` は **UTF-8（BOM なし）** で保存されています。
編集して Shift_JIS で保存し直すと文字化けします。

### SQL の書き方

画面から来た値を文字列連結で SQL に埋めている箇所はありません。
すべて `DbQuery` / `DbExec` のパラメータ経由です。
画面を追加するときも、この 2 つ以外で SQL を組まないでください。

```vbscript
' 良い
DbExec "UPDATE [T_受電] SET [件数]=? WHERE [受電ID]=?", Array(cnt, rowId)

' 駄目
gConn.Execute "UPDATE [T_受電] SET [件数]=" & cnt & " WHERE [受電ID]=" & rowId
```

### バックアップ

`日報集計_be.accdb` を日次でコピーしてください。
共有フォルダのバックアップに含まれていれば別途の作業は不要です。

### 最適化／修復

Access ファイルは使い込むと膨らみます。月 1 回、誰も使っていない時間に
Access で開いて「データベース ツール」→「データベースの最適化/修復」を実行してください。

### 同時利用の目安

Access（ACE）は数十人規模までです。それを超えるなら SQL Server Express への
移行を検討してください。SQL はすべてパラメータ渡しで書いてあるので、
変更が要るのは `include/db.asp` の接続文字列だけです。

---

## つまずきやすいところ

| 症状 | 原因と対処 |
|---|---|
| `Provider が見つかりません` | ACE 未導入、またはアプリケーションプールのビット数が不一致 |
| `外部データベースを開けません` | `.accdb` を置いたフォルダに書き込み権限が無い |
| 文字化けする | `.asp` を Shift_JIS で保存し直してしまった |
| 右上の名前が「(未認証)」 | 匿名認証が有効なまま。IIS で無効にする |
| 全員がマスタ保守を開ける | `auth.asp` の `ADMIN_USERS` が空のまま |
| 印刷が 2 枚になる | 印刷倍率が 100% でない、または記述欄が長い |
