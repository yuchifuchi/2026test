# 03 困ったとき

- まず「設置チェック」を開いてください: `http://サーバー名/nippou/staff/setup_check.asp`
  （パート職員用のフォルダは `http://サーバー名/nippou/part/setup_check.asp`）
- 設置チェックでは、上から順に「よい」「注意」「だめ」が並びます。**いちばん上の「だめ」（赤い行）が原因であることが多い**ので、その行の「項目」を下の表で探してください。
- 画面に「うまく動きませんでした」と出たときは、表の 5 行（ファイル名・行番号・内容・種別・URL）をそのままシステムの担当に知らせてください。

## 2. 設置チェックの「6. 画面」の見方（probe1～7）

設置チェックのいちばん下の「6. 画面」には、probe1～probe7 という切り分け用のページの結果が並びます。
番号が大きくなるほど、読み込む部品が 1 つずつ増えます。**最初に赤くなった番号**で、どこが壊れているかが分かります。

| 最初に赤くなった番号 | 壊れている所 | 対処 |
|---|---|---|
| probe1 | ASP そのもの | 3-1 |
| probe2 | include\config.asp（設定ファイル）の書き方 | 3-8 の書き方を見て直す。分からなければ納品物の config.asp をコピーし直し、DB_PATH だけ書き直す |
| probe3 | include\sql.asp | 納品物の include フォルダをコピーし直す |
| probe4 | include\db.asp、または DB_PATH を場所に直せない | 3-8 |
| probe5 | データベースに接続できない | 設置チェックの「3. データベース」の赤い行を見る（3-5・3-8） |
| probe6 | include\auth.asp | 納品物の include フォルダをコピーし直す |
| probe7 | include\layout.asp、または css | 納品物の include・css フォルダをコピーし直す |
| すべて よい なのに画面が だめ | その画面のファイル | その行の「内容」を知らせる |

> include フォルダをコピーし直すときは、include\config.asp だけは今のものを残してください（置き場所の設定が入っています）。

## 3. 対処のしかた

### 3-1. ASP が入っていない

サーバーの管理者に頼む作業です（サーバーの機能を足す作業で、IIS の設定の変更ではありません）。

1. サーバーで「サーバー マネージャー」を開きます。
2. 右上の「管理」をクリックし、「役割と機能の追加」をクリックします。
3. 「次へ」を 3 回クリックし、「サーバーの役割」の画面にします。
4. 一覧の「Web サーバー (IIS)」の左の ▷ をクリックして開きます。
5. 「Web サーバー」→「アプリケーション開発」と開きます。
6. 「ASP」にチェックを入れます（関係する機能を足すか聞かれたら「機能の追加」をクリックします）。
7. 「次へ」を押して進み、「インストール」をクリックします。

**できたことの確かめ方**
`http://localhost/nippou/part/probe1.asp` を開くと「PROBE1-OK」と出ます。

### 3-2. 「HTTP エラー 500.19」

web.config（part・staff・data の 3 つのフォルダにあります）に、IIS がフォルダごとには変えさせない設定（ASP の設定・認証・IP アドレスの制限など）が書き加えられると、そのフォルダのすべての画面がこのエラーになります。

1. 納品物の `nippou\part\web.config`・`nippou\staff\web.config`・`nippou\data\web.config` を、それぞれ同じ名前のフォルダにコピーし直します。

**できたことの確かめ方**
設置チェックが開け、「web.config」の行が「よい」になります。

> ASP の設定や IP アドレスの制限が必要になったときは、web.config には書かず、IIS マネージャーの画面で設定してください。

### 3-3. 「An error occurred on the server…」だけが出る

エラーの説明画面（error.asp）が使われていません。

1. その画面のフォルダ（part か staff）に `error.asp` と `web.config` があるか確かめます。無ければ納品物からコピーします。
2. システムを `C:\inetpub\wwwroot\nippou` 以外の場所に置いたときは、web.config の中の `/nippou/part/error.asp`（staff は `/nippou/staff/error.asp`）が、置いた場所と合っていません。所定の場所に置き直してください。

**できたことの確かめ方**
エラーが起きたとき、赤い帯の「うまく動きませんでした」と、5 行の表が出るようになります。

### 3-4. 「うまく動きませんでした」と出た

画面に出ている表の 5 行（ファイル名・行番号・内容・種別・URL）を、そのままシステムの担当に知らせてください。枠の中をコピーしてメールに貼り付けても構いません。
「内容」の上に、次にすることが書かれていることがあります（例:「データベースのフォルダに書き込みの許可がありません」）。そのときは、その案内に従ってください。

### 3-5. 「ACE で接続」が だめ

ACE（Microsoft Access データベース エンジン）は、データの入れ物（.accdb）を読み書きする部品です。

1. 設置チェックの「1. サーバー」の「32 / 64 ビット」の行を見ます（ふつうは「64 ビットで動いています」）。
2. サーバーの管理者に、その行に出ているのと同じビット数の「Microsoft Access データベース エンジン 2016 再頒布可能コンポーネント」を入れてもらいます。

**できたことの確かめ方**
設置チェックの「ACE で接続」が「よい」になり、probe5 が「よい」になります。

> サーバーに 32 ビット版の Office が入っていて、64 ビット版のエンジンが入れられないと言われたときだけ、IIS マネージャーで次の 1 か所を変えてもらいます（このシステムで IIS マネージャーを触るのは、この場合だけです）:
> IIS マネージャー → 左の「アプリケーション プール」→「DefaultAppPool」を右クリック →「詳細設定」→「32 ビット アプリケーションの有効化」を「True」→「OK」

### 3-6. 「一時フォルダ（ACE の作業用）」が 注意／「未定義のエラー」と出る

ACE は、集計のときに Windows の一時フォルダに作業用のファイルを作ることがあります。そこに書けないと、データが増えたときに「未定義のエラー」で止まります。

1. 設置チェックのその行に出ているフォルダ（例 `C:\Windows\Temp`）を、サーバーのエクスプローラーで開きます（一つ上のフォルダで、そのフォルダを右クリックします）。
2. 「プロパティ」→「セキュリティ」→「編集」→「追加」と進みます。
3. 「場所」でこのサーバー自身を選び、`IUSR` を入れて「名前の確認」→「OK」をクリックします。
4. 「IUSR」の「変更」の「許可」にチェックを入れ、「OK」を 2 回クリックします。

**できたことの確かめ方**
設置チェックの「一時フォルダ（ACE の作業用）」が「よい」になります。

### 3-7. part と staff の取り違え

part と staff のフォルダには、ほとんど同じファイルが入っていますが、次の 2 つだけ中身が違います。

| ファイル | 違い | 取り違えると |
|---|---|---|
| include\config.asp | `Const ROLE = "part"` か `"staff"` か | part のフォルダが職員用として動く／staff の職員用の画面が「この画面は職員用です」で止まる |
| web.config | エラーの説明画面の場所（/nippou/part/ か /nippou/staff/ か） | エラーのとき、もう片方のフォルダの説明画面が出る（使えるが、設置チェックで注意になる） |

1. 納品物の `nippou\part\include\config.asp` を `C:\inetpub\wwwroot\nippou\part\include` に、`nippou\staff\include\config.asp` を `C:\inetpub\wwwroot\nippou\staff\include` にコピーし直します（DB_PATH を書き換えていたときは、書き直します）。
2. web.config も同じように、同じ名前のフォルダへコピーし直します。

**できたことの確かめ方**
part と staff の両方で設置チェックを開き、「いまの役割」「web.config」が「よい」になります。

### 3-8. データベースの場所（DB_PATH）

data フォルダを所定の場所（`C:\inetpub\wwwroot\nippou\data`）に置いたときは、DB_PATH を書き換える必要はありません。
別の場所に置くときだけ、part と staff の両方の `include\config.asp` をメモ帳で開き、次の 1 行の " " の中を書き換えます。

```
Const DB_PATH = "/nippou/data/日報集計_be.accdb"
```

書き方は 3 通りあります。

| 置いた場所 | 書き方の例 |
|---|---|
| サイトの中（ふつう） | `"/nippou/data/日報集計_be.accdb"` |
| サーバーのドライブ上 | `"D:\data\日報集計_be.accdb"` |
| ほかのパソコンの共有フォルダ | `"\\サーバー名\共有\日報\日報集計_be.accdb"` |

- `..` は使えません。
- " を消したり、行の終わりに文字を足したりすると、全部の画面が開けなくなります（設置チェックの「config.asp の書き方」が だめ になります）。
- 保存するときは、メモ帳の「名前を付けて保存」の「文字コード」を「UTF-8」にします（「UTF-8 (BOM 付き)」にはしません）。
- data フォルダを別の場所に置いたときも、そのフォルダに 01_設置手順 の 3 段目の「書き込みの許可」を付けてください。

**できたことの確かめ方**
設置チェックの「場所」に置いた場所が出て、「ファイル」「ACE で接続」が「よい」になります。

### 3-9. 「ファイルの形式」が だめ

データの入れ物が、Access 2016 専用の形式で保存し直されています。この形式は、課の Access（Microsoft 365）でも開けません。

1. 月末に取った控え（02_運用手順 の D）を data フォルダに戻します。
2. 控えが無いときは、システムの担当に連絡してください。

### 3-10. BOM・文字化け

.asp のファイルをメモ帳で開いて「UTF-8 (BOM 付き)」や「ANSI」で保存すると、画面が開かなくなったり、日本語が読めない字になったりします。

1. そのファイルを、納品物から同じ場所にコピーし直します（include\config.asp のときは、DB_PATH を書き直します）。

**できたことの確かめ方**
設置チェックに BOM の赤い行が出なくなります。

### 3-11. PDF を作れない

1. 設置チェックの「4. PDF」を見ます。
2. 「Microsoft Edge」が だめ のときは、その行に出ている場所を確かめ、part と staff の `include\config.asp` の `PDF_EDGE_EXE` を、Edge のある場所に書き換えます（よくあるのは `C:\Program Files\Microsoft\Edge\Application\msedge.exe`）。
3. 「作業フォルダ」が だめ のときは、data フォルダの「書き込みの許可」（01_設置手順 の 3 段目。IIS_IUSRS も必要です）を確かめます。
4. それでもできないときは、「PDF の試し作成」の行の内容をシステムの担当に知らせてください。

**急ぐときの印刷**
職員メニューの「帳票を見る・PDF にする」で帳票を画面に出し、Ctrl キーを押しながら P キーで印刷します（用紙は A4・縦、「ヘッダーとフッター」を外す）。

### 3-12. 数が合わない気がする

このシステムでは、日報の紙・日報の画面・週の集計表・入力画面の合計を、すべて同じデータ（受付入力の数）から毎回数え直しています。そのため、紙と画面で数が食い違うことは、作りの上で起きません。

1. 職員メニューの「入力もれチェック」で、その日を開きます。
2. 「人ごとの入力」で、入れ忘れの人がいないか見ます。
3. 「数の突き合わせ」が「一致」になっていることを見ます。「不一致」のときは、表の文をそのままシステムの担当に知らせてください。
4. 区分の「日報の列」をあとから変えると、過去の日の数も変わります（04_マスタの直しかた）。変えていないか確かめます。
