# データベース設計（システムの担当の方向け）

データはすべて `nippou\data\日報集計_be.accdb` の 1 つのファイルに入っています。
Access は「データの入れ物」としてだけ使っています。フォーム・レポート・保存クエリは 1 つもありません。
画面（ASP）から、ADO と `Microsoft.ACE.OLEDB.12.0`（無ければ 16.0）で読み書きします。

- ファイル形式: Access 2007-2016 形式（ファイル先頭から 0x14 バイト目が `0x02`）。Access 2010 以降のどれでも開けます。
- 出荷時: マスタ（集計列・ブロック・製品・区分・業務項目）だけ初期データあり。`M_担当者` と実績の表は空。

---

## 1. いちばん大事な決まり：数の出どころは T_受電 ただ 1 つ

日報の紙・日報の画面・週の集計表・受付入力の画面の合計・入力もれチェックは、すべて
`include\sql.asp` の `SqlCallsBase()`（T_受電 に区分・担当者をつないだ 1 本の SELECT）から、その都度数えます。

- 合計を別の表にためておくことはしません（ためた数が古くなる・二重に数える、が起きないように）。
- 現行の Excel は「入力シート → 転記シート → 集計表」と経路が 2 本あり、そこで数が食い違いました。経路を 1 本にすれば、食い違いは作りの上で起きません。
- 入力もれチェックは、T_受電 を直接数えた数と、上の SELECT を通した数を突き合わせ、食い違えば赤で出します（参照整合性があるので、通常は必ず一致します）。

## 2. 表

### マスタ

| 表 | 内容 | 主キー | 主な列 |
|---|---|---|---|
| M_集計列 | 日報の 5 列（申込・抽選・払込用紙・商品発送・その他） | 集計列ID | 集計列名、表示順 |
| M_ブロック | 受付入力の大きなまとまり | ブロックID | ブロック名、製品別（True なら製品を列に並べる）、表示順 |
| M_製品 | 商品 | 製品ID | ブロックID、製品名、適用開始日、適用終了日、表示順、有効 |
| M_区分 | 電話の区分 | 区分ID | ブロックID、区分名、**集計列ID（日報のどの列に積むか）**、内訳区分（"交換"／"返金"）、表示順、有効、旧転記名 |
| M_担当者 | パート職員・正規職員 | 担当者ID | 担当者コード（席番号。再利用するので UNIQUE にしない）、姓、名、氏名、カナ、ログオン名、職員区分（"パート"／"職員"）、在籍開始日、在籍終了日、表示順、有効、備考 |
| M_業務項目 | 電話以外の業務 ①～⑬ | 業務項目ID | 番号、項目名、帳票表示名、表示順、有効 |

- `M_製品` の 製品ID = 0 は「製品指定なし」。製品を伴わない区分の実績は 製品ID = 0 で持ちます。
- `M_区分.[集計列ID]` は、現行 Excel ではシートの 2 行目に埋め込まれていて見えなかった情報です。マスタ保守の画面でいつでも見られます。

### 実績

| 表 | 1 行の意味 | 主キー | 一意の制約 |
|---|---|---|---|
| T_日報 | 1 日の日報（回線数・記述欄 3 つ・状態） | 対象日 | ― |
| T_出勤 | 1 日・1 人の出勤（勤務時間・備考） | 出勤ID | UQ_出勤（対象日, 担当者ID） |
| T_受電 | 1 日・1 人・1 区分・1 製品の件数 | 受電ID | UQ_受電（対象日, 担当者ID, 区分ID, 製品ID） |
| T_業務実績 | 1 日・1 人・1 業務項目の件数 | 実績ID | UQ_業務実績（対象日, 担当者ID, 業務項目ID） |

- T_受電 は、製品が無いときも 製品ID = 0 を入れ、NULL を使いません。NULL を使わないことで一意の制約が確実に効き、二重計上が作りの上で起きません。
- 画面は「その欄の今の件数」で上書き保存し、0 にした欄は行を消します（足し込まない）。
- `T_日報.[状態]` が "確定" の日は、受付入力・その他業務を保存できません（確定を取り消すと直せます）。
- 対象日はいつも 0 時（日付だけ）で保存します。SQL はどれも「その日の 0 時以上・翌日の 0 時未満」で探し、日ごとにまとめるときは時刻を落とした日付でまとめます（Access で直接直して時刻が入っても、日が割れないように）。

## 3. SQL の決まり（include\sql.asp）

ASP から ACE OLEDB で使うため、Access の画面の中でだけ使える書き方は使いません。

| 決まり | 理由 |
|---|---|
| 保存クエリを作らない。SQL は sql.asp に文字列で持つ | 保存クエリの中に Access 専用の関数があると、実行して初めて落ちる |
| `Nz()` を使わない。`IIf(IsNull(Sum(x)), 0, Sum(x))` を使う | Nz は Access アプリの関数で、ASP からは「関数 'Nz' は定義されていません」で落ちる |
| 値は必ず `?` で渡す（文字列でつながない） | 入力された文字で SQL が壊れないように |
| 派生表の外で ORDER BY に使う列は、内側の SELECT にも入れる | 入っていないと ACE で落ちる |
| JOIN が 2 つ以上なら `(A JOIN B ON ..) JOIN C ON ..` とかっこで囲む | ACE の決まり |
| ON には「表.[列] = 表.[列]」だけを書く。日付などで絞るのは派生表の中で | ON に定数や ? を書くと「JOIN 式はサポートされていません」になることがある |
| ORDER BY・GROUP BY には「別名.[列]」だけを書く | SELECT 句の別名を書くと「パラメーターが少なすぎます」になることがある |
| 空欄は空文字ではなく Null で保存する | 「未入力」の調べ方を 1 通りにするため（列も空文字を許さない設定） |

## 4. 直接 Access で開くとき

- 開いても構いませんが、表の名前・列の名前・型は変えないでください。
- 別の形式で保存し直さないでください（Access 2016 専用の形式 `0x05` になると、課の Access でも開けません）。
- 誰かがシステムを使っている間は開かないでください（data フォルダに `日報集計_be.laccdb` があるときは使用中です）。

## 5. このファイルの作り方（開発者向け）

`日報集計_be.accdb` は、ソースの `db/schema.sql`（表の定義と初期データを書いた 1 本のファイル）から、Java の Jackcess 4.0.5 で作っています（Windows も Access も使わずに作れるように）。
作ったあと、ファイル形式のバイト（0x02）、表・索引・関連・初期データが schema.sql のとおりかを、別の読み方で突き合わせて確かめています。
