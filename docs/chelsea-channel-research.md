前提: 運営者本人がチェルシーファン。既存資産 = market-video パイプライン(データ取得→Remotion→TTS→GitHub Actions 毎朝自動生成)。
判定基準はユーザー設定の方針に従う: 「必ず再生数が回る固いもの」「短期で収益」。お世辞・慰めなしのストラテジスト基準で記述する。

## 2. データ・権利面の実現可能性(既存パイプラインとの適合)

| 項目 | 判定 |
|---|---|
| データ源 | football-data.org 無料枠(10req/分・クレジット表記必須)+ API-Football 無料100req/日。**プレミアはスポーツの中で最もAPIが整っている** |
| 試合映像 | 使用不可(権利厳格)。ただし**プレチャンが「映像なし観戦ライブ」で成立を実証済み**。当方の様式=データ・図解動画なので最初から映像不要 |
| 選手名・スコア | 事実データに著作権なし。報道文脈での選手名使用は可。ロゴ・写真・放送映像は不可 |
| Transfermarkt市場価値 | 編集部推定値のため転載しない(移籍の事実のみ扱う) |
| 既存パイプライン流用 | fetch(API差し替え)→ brief(試合結果・スタッツ・順位表)→ Remotion(パネル様式そのまま)→ TTS → Actions cron。**構造は市況動画と同型** |

## 3. 投稿設計(週末集中リズム対応)

サッカーは市況と違い平日毎日のデータ供給がない。試合は週末+ミッドウィーク。設計はこれに合わせる:

- **試合翌朝(自動)**: データレビュー動画 — スコア・xG等スタッツ・順位表・次節。既存の「毎朝6:30 Actions」の試合日版
- **平日(半自動)**: 移籍・ニュース図解。移籍市場期(夏・冬)はデイリー化 — 移籍期は需要が最大化する
- **試合日(手動・任意)**: 映像なし同時視聴ライブ。自動化不能だが、YouTubeの inauthentic-content 対策として「人間がいるチャンネル」の証明になる
- **データ企画(月次)**: スカッド年齢表・契約年数・BlueCo経営分析(「人員整理企画」系が総合チャンネルで再生されている=需要確認済み)
- **X連動必須**: 既存コミュニティ(@ChelseaTokyoJP等)が初期流入源

## 4. ストラテジスト判定(お世辞なし)

### 強み
- 空白度4.5/5 + 受け皿実在 + 先行成立例あり。「固い再生」の条件である**確実な定期需要(試合)**がある
- 運営者本人がファン=市況チャンネルの最大の弱点だった「自分が見ない動画を作る」問題が消える。プレチャン視聴者として「良い動画」の基準を体感で持っている
- 映像不要様式なので権利リスクほぼゼロ、既存パイプラインの流用率が高い

### 弱み(直視すべき点)
1. **「短期で収益」とは両立しない。** 収益化ライン(登録1,000人+長尺4,000時間)まで、空白ニッチでも数ヶ月はかかる。母数=日本のチェルシーファン人口はリヴァプール・アーセナルより小さい可能性が高い(日本人選手不在)
2. RPMは金融系より低い(スポーツ・エンタメ帯)。天井目安はプレチャン(19〜24万)の1クラブ分 = **1年で1〜3万人が現実線**
3. 週末集中リズム=平日の弾は移籍・ニュース依存。移籍期以外の平日は供給が細る
4. 完全自動は不可。試合レビューの「考察」部分は本人の視点が必須(これは方針①とも整合)

### 結論

**参入推奨(GO)。ただし「短期収益の柱」ではなく「固い再生が読める本命チャンネル」として。**
短期収益はこのチャンネルには期待しない。市況Shorts自動生成(稼働済み)は素材・実験として並走可能。

## 5. 参入する場合の初手

1. football-data.org 無料キー取得(要クレジット表記)
2. 既存パイプラインを試合翌朝レビュー用に改造(fetch→brief→Remotion様式流用)
3. チャンネル名・X垢を先に確保、@ChelseaTokyoJP 周辺で認知
4. 8月の移籍市場デッドライン+開幕(8月中旬)が最初の需要ピーク = **参入タイミングとしては今が最適**
