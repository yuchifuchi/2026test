# 業務システム調達ナレッジの商品化

社内SEとしての業務システム調達の経験を、note の有料記事 + Excelテンプレートとして商品化するための一式。

## 方針

コモディティ化しないのは「既存情報の再配置」ではなく **独自の入力(一次情報)** と **流通(読者)**。
このディレクトリの資産は、以下の構造で組んでいる。

| 層 | 役割 | 中身 |
|---|---|---|
| 集客 | 無料記事7本 | 調達プロセスの実践記録 |
| 即金 | 有料記事3本 + テンプレ | 質問リスト・稟議構成・契約前チェック・評価シート |
| 資産 | 構造化データ | 評価項目・観点・質問リスト(generator/items.py) |

読者は「1〜2年前の自分」。専門家として書かず、**実践記録として書く**。

## Excelシートの構成

| シート | 役割 |
|---|---|
| 00_使い方 | 目的・進め方・色の意味・Must判定の説明・免責 |
| 01_重み付け設定 | 6大分類の重み配分。プリセット4パターン、合計100チェック |
| 02_比較評価シート | 本体。ベンダー名 → 費用(5年TCO自動算出)→ 29項目を1〜5で評価 |
| 03_稟議用サマリ | 総合点・順位・選定候補順位・レーダーチャート・稟議文面 |
| 04_記入例 | 架空案件(販売管理システム刷新・製造業120名)を3社ぶん記入 |
| 05_ベンダー質問リスト | 30問。分類・質問・なぜ聞くか・4社分の確認欄 |

### 設計上の要点

- **Must と点数を分離**。必須項目で2以下があると総合点に関わらず「要再検討」。
  選定候補順位は Must合格社だけで付け直すので、点数1位と選定候補1位の食い違いに気づける
- **5年TCO で比較させる**。初期費用だけの比較を構造的に不可能にする
- **買った側しか書けない項目を仕込む** — 自社側の工数(人日)、保守の有償範囲、
  契約終了時のデータ持ち出し可否、法改正対応の費用負担
- 各項目に「確認の観点」を1行付ける。ここが商品の実体

## シートを作り直す

評価項目・質問リストは `generator/items.py` に分離してある。ここを直して再生成する。

```bash
pip install openpyxl
cd generator
python3 build.py "../業務システム調達_ベンダー比較評価シート_v1.xlsx"
```

### 検証

数式は openpyxl が書くためキャッシュ値を持たない(Excel で開いた瞬間に全再計算される)。
LibreOffice による再計算検算が使えない環境向けに、2種類の検証を用意している。

```bash
# 静的検証: 互換性リスクのある関数、結合セルへの書き込み、行レイアウト整合、
#           記入例の期待値を別ロジックで独立計算して照合
python3 verify.py "../業務システム調達_ベンダー比較評価シート_v1.xlsx"

# 数式評価: 全セルを実際に評価してエラー値(#REF! 等)がないことを確認
pip install formulas
python3 evaluate.py "../業務システム調達_ベンダー比較評価シート_v1.xlsx"

# 実データ投入テスト: 記入例データを 02 に流し込み、03 の順位・稟議文面を確認
python3 smoke_summary.py "../業務システム調達_ベンダー比較評価シート_v1.xlsx"
```

使用関数は Excel 2007 以前のものだけに絞っている(`SUMPRODUCT` / `AVERAGEIFS` /
`INDEX` / `MATCH` / `RANK` / `IFERROR`)。古い環境の企業でも開ける。

## 未検証・要確認

- **03_稟議用サマリ のレーダーチャート**は実機未確認。最初に Excel で開いたときに要チェック
- フォントは Meiryo 固定(想定読者が Windows + Excel の企業ユーザーのため)
- note はファイルを直接添付できないため、有料エリアに外部ストレージの共有リンクを貼る運用になる。
  リンク発行後、必ず別アカウントから開けるか確認する
