# 商品パッケージ設計:note 有料記事 + ベンダー比較評価シート

## 商品の位置づけ

| | 内容 |
|---|---|
| 商品名(案) | 業務システムのベンダー選定で失敗しないための評価シート(29項目・重み付け・Must判定つき) |
| 価格 | 2,000円(初回)→ 実績が出たら 2,980円 |
| 形式 | note 有料記事 + 記事内にExcelファイルの配布リンク |
| 想定読者 | 初めて業務システムの調達・ベンダー選定を任された情シス/総務/経営企画の担当者 |
| 一言の約束 | 「ベンダーに会う前に、評価軸と優先順位を確定させる」 |

## 記事構成(無料部分 / 有料部分の切り分け)

### 無料部分 ─ ここだけで独立した価値を出す

1. **冒頭:失敗の型を5つ提示**
   - 評価軸を後から作る → 提案書の上手いベンダーが勝つ
   - 機能比較しかしない → 移行工数・5年後のコスト・保守の有償範囲が抜ける
   - ○×で比較する → 全社○になって差がつかない
   - 「なんとなく良さそう」→ 稟議で説明できず差し戻し
   - 必須要件を満たさない会社が総合点で勝ってしまう

2. **評価軸は6つに分ける**(大分類と、それぞれで何を見るかを全部書く)
   - ここは出し惜しみしない。読んだだけで役に立つ状態にする

3. **重み付けの決め方**(プリセット4パターンの考え方まで無料で公開)
   - 「この案件が失敗するとしたら原因は何か」から逆算する

4. **見積書に絶対に出てこない3項目**(記事の目玉。無料で出す)
   - 自社側に必要な工数(人日)
   - 保守契約の、どこからが有償か
   - 契約終了時のデータ持ち出し可否

5. **Must と点数を分ける、という考え方**
   - なぜ点数だけの運用が事故るのか

→ ここまでで「この人は分かっている」と伝わる。**無料部分だけで完結した読み物**にすること。

### 有料部分(¥2,000)

6. 29項目の評価項目 全リスト(項目名 + 確認の観点)
7. ベンダーへの質問30問(何を、なぜ聞くか)
8. **Excelファイル配布リンク**(全6シート)
9. 記入例の解説 ─ 架空案件で「総合1位がMust失格になる」ケースを読み解く
10. 稟議書への転記のしかた

## Excelファイルの構成(納品済み v1)

| シート | 役割 |
|---|---|
| 00_使い方 | 目的・進め方・色の意味・Must判定の説明・免責 |
| 01_重み付け設定 | 6大分類の重み配分。プリセット4パターン、合計100チェック付き |
| 02_比較評価シート | 本体。ベンダー名 → 費用(5年TCO自動算出)→ 29項目を1〜5で評価 |
| 03_稟議用サマリ | 総合点・順位・選定候補順位・レーダーチャート・稟議文面のたたき台 |
| 04_記入例 | 架空案件(販売管理システム刷新・製造業120名)を3社で埋めた実例 |
| 05_ベンダー質問リスト | 30問。分類・質問・なぜ聞くか・4社分の確認チェック欄 |

## 配布の実務

- note は記事にファイルを直接添付できない → **有料エリアに Google Drive の共有リンクを貼る**
- 「リンクを知っている全員が閲覧可」に設定し、**別アカウントから必ず開けるか確認する**
- ファイル名にバージョンを入れる(v1, v1.1...)。更新したら記事の冒頭に更新履歴を追記する
- 購入者からの指摘で改善したら、次バージョンに反映して記事を更新 → 「買った後も更新される」が再購入と口コミにつながる

## 販売前にやること

1. X で無料部分の内容を分割して投稿し、**反応が取れたテーマを記事の見出しにする**(作ってから売り先を探さない)
2. 実際に自分が調達に使ってみる。使いにくかった箇所は必ず購入者にも刺さる
3. 免責文を入れる(納品済みファイルの 00_使い方 に記載済み)
